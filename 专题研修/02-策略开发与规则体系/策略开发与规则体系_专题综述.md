# 一、规则的认识与分类

## 1.1 规则的概念

规则是**基于变量（特征）的一系列判断条件组合**。

核心理解：

1. 规则基于特征变量产生，因此数据和变量是制定规则的先决条件。
2. 规则可以是一个判断条件，也可以是多个判断条件的组合。
3. 规则层位于数据层与决策层之间：
   - **数据层**：变量或特征，如年龄、性别、查询次数、逾期次数；
   - **规则层**：对变量设置的判断条件；
   - **决策层**：输出通过、拒绝、转人工审核等业务决策。

示例：

```text
单条件规则：年龄 > 60
组合规则：性别 = 男 AND 年龄 > 60
```

## 1.2 规则的作用

规则的主要作用是**筛选和细分客户**，可按风险维度对客群进行划分。

在信贷风控中，规则主要用于：

- 识别不同风险水平的人群；
- 拒绝高风险人群；
- 通过低风险人群；
- 对特定风险点进行直接拦截；
- 规避潜在信用风险。

示例：

```text
变量：过去 12 个月的逾期次数
规则：逾期次数 > 3
处置：满足条件则拒绝，否则通过
```

示例中，被拒绝客群逾期率约 8%，通过客群逾期率约 2%，说明该规则具有风险区分能力。

## 1.3 规则与策略的关系

在信贷风控中：

- **规则和模型都是策略的工具**；
- 策略是对数据、规则、模型、流程顺序和处置方式的综合管理；
- 一个完整策略通常需要明确：
  - 使用哪些数据；
  - 使用哪些规则和模型；
  - 阈值如何设置；
  - 规则和模型的调用顺序；
  - 在流程中的部署位置（哪个决策节点）；
  - 命中后采取何种处置（拒绝、通过或转人工）。

典型贷前授信审批流程：

```text
客户申请 → 规则判断 → 模型评分 → 决策结果
                    ↑
                   数据
```

规则只负责自身的风险识别能力，整个决策编排属于策略层。

## 1.4 规则的特点

与模型相比，规则具有以下特点：

1. **可识别特定风险**：适合针对明确的风险场景进行拦截；
2. **可解释性更强**：判断依据清晰、直接，便于上线、审计和运营；
3. **灵活性更高**：可以根据风险变化快速调整阈值或条件；
4. 更便于配置、监控和迭代维护。

对比：

- 模型：基于大量特征，利用逻辑回归、机器学习等算法输出概率或分数；
- 规则：通常是对单个变量或少量变量进行条件判断；
- 可以将模型理解为"一条由大量复杂规则共同形成的复杂规则"。

## 1.5 规则的分类

规则可从三个维度分类：数据维度、策略维度、强弱维度。

### 1.5.1 按数据来源分类

数据主要来源于征信报告和第三方数据源。

**1）征信类规则**

基于征信报告衍生的风险判断规则，例如：

- 征信查询次数；
- 历史逾期次数；
- 当前逾期状态；
- 信用账户数量；
- 历史还款表现；
- 当前负债及授信情况。

**2）多头共债类规则**

从征信报告和第三方数据中获取多头借贷行为信息，用于识别：

- 多平台申请次数；
- 多机构借款数量；
- 近 1/3/6/12 个月多头行为；
- 短期频繁申请、现金贷或小贷活跃程度。

**3）欺诈类规则**

依赖第三方数据识别疑似欺诈行为，例如：

- 欺诈名单、团伙关联；
- 身份欺诈、设备欺诈；
- 异常设备或异常联系人；
- 信息伪造、异常注册和异常申请行为。

**4）运营商类规则**

通过通信运营商数据评估风险，例如：

- 手机号在网时长；
- 通话活跃度；
- 联系人结构；
- 运营商逾期或欠费；
- 号码稳定性。

**5）司法类规则**

通过司法数据评估风险，例如：

- 被执行信息；
- 法院涉诉；
- 限高（限制高消费）；
- 失信记录。

**6）设备类规则**

通过 SDK 获取设备数据，例如：

- APP List；
- GPS；
- IP；
- 设备型号；
- 系统版本；
- 模拟器、Root、越狱等设备环境风险。

**7）消费类规则**

通过银行卡消费和支付数据评估：

- 收入与消费能力；
- 消费稳定性；
- 消费结构；
- 异常交易；
- 资金紧张程度。

### 1.5.2 按策略用途分类

**1）准入规则**

年龄、职业、地域、身份条件等基础限制，通常依据公司监管要求和产品政策制定。

**2）黑名单规则**

包括内部和外部黑名单，可细分为：

- 逾期类；
- 法院类；
- 限高类；
- 欺诈类；
- 内部拒绝名单。

黑名单客户通常属于风险较高人群。

**3）反欺诈规则**

针对个人欺诈和团伙欺诈，常用：

- 设备信息；
- 通讯录；
- 地址定位；
- 埋点信息；
- 行为轨迹；
- 关联网络。

**4）身份核验规则**

用于校验：

- 姓名、身份证、手机号三要素一致性；
- 在网状态；
- 联系人号码状态；
- 实名信息一致性。

**5）多头共债规则**

识别借款人的多头借贷和共债行为，数据主要来自征信和第三方数据。

**6）评分规则**

将模型输出映射为规则判断，例如：

- 综合评分；
- 欺诈分；
- 信用分；
- 消费分。

评分本身可以作为一条效果较强的规则，例如：低于某分拒绝、中间分转人工审核、高于某分自动通过。

### 1.5.3 按强弱程度分类

**强规则（Hard Check）**

- 条件设置严格；
- 命中后通常代表高风险；
- 一般不轻易调整；
- 常直接拒绝。

示例：历史逾期次数超过 10 次、命中黑名单、命中强欺诈规则、身份核验严重异常。

**弱规则（Soft Check）**

- 条件更柔和、更灵活；
- 多为连续数值变量；
- 常用于信用风险评估；
- 阈值需要随客群风险变化持续调整；
- 是策略分析人员日常调优的重点。

示例：信用分越低风险越高、多头申请次数过高、消费或设备类风险变量异常。

### 1.5.4 设备规则案例

示例展示了一组基于设备数据制定的规则，字段包括规则类别、基础数据、数据层级、规则名称、规则描述、规则强度与处置方式。代表性规则如下：

| 规则方向 | 变量示例 | 规则含义或阈值示例 |
|---|---|---|
| 设备信息 | 是否为样机 | 设备是否为样机，强规则 |
| 设备信息 | 手机设备首次发布时间距今月份 | 设备过旧，例如超过 36 个月 |
| 设备使用情况 | 开机天数 | 设备开机天数过短或过长 |
| 设备使用情况 | 沉默天数 | 设备长期未使用 |
| 设备使用情况 | 上月使用移动流量 | 流量极低，例如低于约 30MB |
| 设备使用情况 | 移动流量能力 | 网络或流量能力异常 |
| 设备使用情况 | 用户体验改进计划开关状态 | 状态异常或关闭 |
| 设备使用情况 | 设备登录过的账号数 | 账号数过多，例如大于 5 个 |
| 设备信息 | EMUI/系统版本号 | 系统版本明显低于主流版本 |
| 设备使用情况 | 常用联网方式 | 仅使用 2G 等异常情况 |
| 个人信息 | 职业判断 | 职业状态与实际使用行为不符 |
| APP 信息 | 当前安装 APP 数量 | 安装数量过少，例如少于 3 个 |
| APP 信息 | 30 天内新安装 APP 记录 | 新装 APP 过多，例如多于 10 个 |
| APP 信息 | 30 天内 APP 使用次数 | 使用次数过少，例如少于 100 次 |

# 二、规则分析全流程

## 2.1 完整流程

规则完整流程包含两大模块：

1. **规则离线开发和评估**；
2. **规则上线验证和监控**。

### 人工制定规则路径

```text
风险识别 → 人工规则 → 变量开发 → 样本选取 → 效果评估
```

### 量化制定规则路径

```text
变量开发 → 样本选取 → 量化规则 → 效果评估
```

### 上线后的闭环

```text
规则上线 → 规则验证 → 规则监控 → 规则调整 → 重新上线
```

规则应形成持续迭代的闭环，而不是一次性配置后长期不动。

## 2.2 人工规则与量化规则

人工规则和量化规则的核心区别：

- **人工规则**：先基于风险认知明确规则目标，再开发对应变量；
- **量化规则**：先批量开发变量，再通过数据分析筛选规则。

二者各有优缺点：

- 人工规则风险目标明确、业务解释性强、开发速度快，但风险覆盖可能不全面、容易依赖经验、对长尾风险的识别能力有限；
- 量化规则能更充分识别数据中的风险，但部分变量可能缺乏解释性；
- 实际业务中二者通常组合使用，互相补充。

### 量化规则的四个核心步骤

1. **变量开发**：对底层数据进行抽象和关联，衍生多维度高级变量。
2. **样本选取**：根据目标定义选取合适样本，定义目标变量，划分训练集、测试集或时间外样本。
3. **量化规则**：通过 WOE/IV、区间坏账率排序、业务解释性筛选变量，结合 Lift 制定阈值；常见形式包括单一规则、交叉表、决策树。
4. **效果评估**：在 OOT 样本（有贷后表现）中评估风险效果，在授信样本（尚无贷后表现）中评估通过率影响。

## 2.3 上线验证与监控

### 1. 规则上线

将完成离线评估的规则配置到决策引擎，并发布到生产环境。

### 2. 规则验证

验证内容包括：

- 线上配置是否正确；
- AB 测试分流比例是否正确；
- 线上规则命中率是否与线下测算接近；
- 字段和阈值是否存在偏差；
- 决策结果是否符合预期。

### 3. 规则监控

按日、周、月持续监控：

- 命中率；
- 通过率；
- 坏账率；
- Lift；
- 客群结构；
- 数据稳定性。

出现异常时需要及时排查。

### 4. 规则调整

根据贷后表现、客群变化和业务目标调整：

- 阈值；
- 规则条件；
- 规则顺序；
- 规则启停；
- 规则集组合方式。

# 三、单变量规则生成

## 3.1 三个主要步骤

1. 对变量进行描述性统计分析，完成变量初筛；
2. 对保留变量进行分箱，计算统计量、WOE 和 IV，进行二次筛选；
3. 基于分箱 IV 分析或极端值检测制定规则阈值。

## 3.2 变量初筛

### 为什么需要初筛

真实项目中往往有数百到数千个变量，不可能全部用于规则开发，原因包括：

- 变量效果有好有坏；
- 变量之间可能重复或高度相关；
- 规则过多会增加策略不稳定性；
- 规则过多会增加开发、配置、监控和维护成本。

初筛主要计算以下统计量：

- 缺失率；
- 众数占比；
- 唯一值数量；
- 均值；
- 最大值；
- 最小值；
- 标准差；
- 数据类型。

对不符合要求的变量进行第一轮删除，以降低后续二次筛选压力。

示例：

| 变量 | 含义 | 缺失率 | 众数占比 | 平均值 | 最大值 | 最小值 | 标准差 |
|---|---|---|---:|---:|---:|---:|---:|---:|
| A | 现行消费贷款机构数 | 5% | 2% | 2.5 | 8 | 0 | 1 |
| B | 近 12 个月旅游出行次数 | 60% | 90% | 0.1 | 1 | 0 | 0 |
| C | 月均夜间短信数 | 10% | 5% | 3 | 50 | 0 | 1.5 |
| D | 同 WIFI 地址一个月出现贷款次数 | 8% | 6% | 2 | 15 | 0 | 0.5 |

变量 B 的缺失率和众数占比过高，信息量较低，应优先剔除。

### Python 示例：描述性统计

```python
import pandas as pd

def simple_statistics(df: pd.DataFrame) -> pd.DataFrame:
    rows = []

    for col in df.columns:
        s = df[col]

        rows.append(
            {
                "Feature": col,
                "Unique_values": s.nunique(dropna=False),
                "Percentage_of_null": s.isna().mean() * 100,
                "Percentage_of_999": (s == 999).mean() * 100,
                "Max_value_rate": (
                    s.value_counts(dropna=False, normalize=True).iloc[0] * 100
                    if len(s) else 0
                ),
                "Type": str(s.dtype),
            }
        )

    return pd.DataFrame(rows)
```

常见初筛规则：

- 缺失率过高；
- 众数占比过高；
- 单一值变量；
- 唯一值数量过少；
- 异常编码占比过高；
- 变量含义不明确；
- 数据稳定性差。

## 3.3 变量分箱与指标计算

### 3.3.1 分箱概念

**分箱定义**：分箱是将连续变量离散化、将多状态离散变量合并为更少组的过程。

**分箱用途**：

- 对变量分层；
- 便于统计分析；
- 降低异常值干扰；
- 增强变量鲁棒性；
- 观察风险随变量变化的趋势；
- 支持 WOE、IV、Lift 和阈值分析。

**分箱注意事项**：

1. 分箱必须覆盖变量全部取值，不能丢失信息；
2. 箱数不宜过多，一般控制在 5–8 箱；
3. 每箱样本占比应具有统计意义，通常建议至少约 5%；
4. 缺失值通常单独成箱；
5. 每个箱应具有业务和统计意义。

### 3.3.2 分箱算法分类

分箱可从两个维度划分：

**按变量类型**：连续变量、离散变量。

**按是否使用目标变量**：

- **有监督分箱**：利用好坏标签，如卡方分箱、决策树分箱、最优分箱；
- **无监督分箱**：不使用目标变量，如等距、等频、聚类分箱。

常见方法：卡方分箱、最优分箱、决策树分箱、等距分箱、等频分箱、K-means 聚类分箱、类别合并、LabelEncoder 后再分箱。

离散变量可先根据类别坏账率、样本量和业务含义进行合并。

### 3.3.3 分箱统计量

示例变量："最近 3 个月新型非银金融机构的查询次数"。

| 分箱 | 好客户数 | 坏客户数 | 总客户数 | 好客户占比 | 坏客户占比 | 总客户占比 | 区间坏账率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| [0.0, 0.5) | 796 | 28 | 824 | 40.20% | 20.59% | 38.94% | 3.40% |
| [0.5, 1.5) | 533 | 36 | 569 | 26.92% | 26.47% | 26.89% | 6.33% |
| [1.5, 2.5) | 301 | 23 | 324 | 15.20% | 16.91% | 15.31% | 7.10% |
| [2.5, 3.5) | 166 | 18 | 184 | 8.38% | 13.24% | 8.70% | 9.78% |
| [3.5, 4.5) | 98 | 11 | 109 | 4.95% | 8.09% | 5.15% | 10.09% |
| [4.5, 16.0) | 86 | 20 | 106 | 4.34% | 14.71% | 5.01% | 18.87% |
| 合计 | 1980 | 136 | 2116 | 100% | 100% | 100% | 6.43% |

**指标含义**：

- **好客户数 / 坏客户数**：每个箱内好坏样本数量；
- **好客户占比**：箱内好客户数 ÷ 全部好客户数；
- **坏客户占比**：箱内坏客户数 ÷ 全部坏客户数；
- **总客户占比**：箱内总客户数 ÷ 全部客户数；
- **区间坏账率**：箱内坏客户数 ÷ 箱内总客户数。

**业务意义**：

- 总客户占比可以近似理解为规则命中率；
- 区间坏账率用于判断风险水平和风险排序；
- 好坏客户占比差异衡量一个箱对坏客户的集中程度；
- 如果高风险箱具有较高坏客户占比和较低好客户占比，说明该区间适合形成拒绝规则。

**观察重点**：

- 区间坏账率是否随变量递增或递减；
- 每箱样本量是否足够；
- 风险排序是否具有业务合理性；
- 高风险区间是否具有明显的风险抬升。

### 3.3.4 WOE：公式与含义

WOE（Weight of Evidence，证据权重）用于衡量某一分箱中好坏客户分布的差异：

$$
WOE_i = \ln\left(\frac{Bad_i / Bad_T}{Good_i / Good_T}\right)
= \ln\left(\frac{Bad_i}{Bad_T}\right) - \ln\left(\frac{Good_i}{Good_T}\right)
$$

其中：

- $Bad_i$：第 $i$ 箱坏客户数；
- $Bad_T$：全部坏客户数；
- $Good_i$：第 $i$ 箱好客户数；
- $Good_T$：全部好客户数。

示例：

$$
WOE_{[0,0.5)} = \ln(20.59\%) - \ln(40.20\%) = -0.6692
$$

| 分箱 | WOE |
|---|---:|
| [0.0, 0.5) | -0.6692 |
| [0.5, 1.5) | -0.0168 |
| [1.5, 2.5) | 0.1066 |
| [2.5, 3.5) | 0.4566 |
| [3.5, 4.5) | 0.4911 |
| [4.5, 16.0) | 1.2196 |

WOE 逐步上升，说明查询次数越多、风险越高。

### 3.3.5 IV：公式与含义

IV（Information Value，信息价值）常用于评估变量对目标变量的预测能力。

每一箱的 IV：

$$
IV_i = \left(\frac{Bad_i}{Bad_T} - \frac{Good_i}{Good_T}\right) \times WOE_i
$$

变量总 IV：

$$
IV = \sum_{i=1}^{n} IV_i
$$

示例：

| 分箱 | WOE | IV |
|---|---:|---:|
| [0.0, 0.5) | -0.6692 | 0.1313 |
| [0.5, 1.5) | -0.0168 | 0.0001 |
| [1.5, 2.5) | 0.1066 | 0.0018 |
| [2.5, 3.5) | 0.4566 | 0.0222 |
| [3.5, 4.5) | 0.4911 | 0.0154 |
| [4.5, 16.0) | 1.2196 | 0.1264 |
| **总计** |  | **0.2972** |

该变量 IV 约 0.2972，具有较好的风险区分能力。

### 3.3.6 IV 使用标准

| IV 范围 | 预测能力 |
|---|---|
| IV < 0.02 | 几乎没有预测力 |
| 0.02 ≤ IV < 0.10 | 弱 |
| 0.10 ≤ IV < 0.30 | 中 |
| 0.30 ≤ IV < 0.50 | 强 |
| IV ≥ 0.50 | 需要排查，可能存在过拟合或数据泄漏 |

变量筛选不能只看 IV：

- 单变量预测能力强，不代表组合后效果最好；
- 需要控制变量间相关性；
- 需要关注分箱坏账率的排序性；
- 需要保证业务可解释性；
- 需要检查跨时间稳定性。

### 3.3.7 IV 的 Python 实现

核心计算逻辑如下：

```python
import numpy as np
import pandas as pd

def calculate_iv(x: pd.Series, y: pd.Series) -> tuple[float, pd.DataFrame]:
    table = pd.crosstab(x, y, margins=True)

    # 假设 0 为好客户，1 为坏客户
    table["good_pct"] = table[0] / table.loc["All", 0]
    table["bad_pct"] = table[1] / table.loc["All", 1]

    eps = 1e-8
    table["woe"] = np.log(
        (table["bad_pct"] + eps) / (table["good_pct"] + eps)
    )
    table["iv_part"] = (
        table["bad_pct"] - table["good_pct"]
    ) * table["woe"]

    iv = table.loc[table.index != "All", "iv_part"].sum()
    return float(iv), table
```

实际使用时需要处理：

- 分母为零导致的无穷 WOE；
- 空箱；
- 极小样本箱（合并）；
- 缺失值单独成箱；
- 特殊值；
- 训练集与 OOT 的分箱一致性。

## 3.4 制定规则阈值

### 3.4.1 规则效果的两个期望

**期望一：拒绝比例不宜过高**

- 拒绝率过高会明显影响通过率和业务规模；
- 风控流程中存在多个筛选环节，各环节应互相补充；
- 单条规则只应拦截最有把握的高风险客群；
- 通常建议单条规则命中率（拒绝比例）不超过约 5%。

**期望二：拒绝客群风险显著更高**

- 拒绝客群中坏客户占比越高越好；
- 拒绝客群中好客户占比越低越好；
- 尽量多抓坏客户，少误杀好客户。

### 3.4.2 五个规则评估项

**1）命中率（hit_rate）**

$$
hit\_rate = \frac{规则命中客户数}{总客户数}
$$

即该规则对总体客户的拒绝比例。

**2）精准率（bad_rate）**

$$
bad\_rate = \frac{规则命中客户中的坏客户数}{规则命中客户数}
$$

精准率应与整体坏账率对比。例如整体坏账率 6%、规则命中客群坏账率 18%，则命中客群风险约为整体的 3 倍。

**3）召回率（recall_rate）**

$$
recall\_rate = \frac{规则命中的坏客户数}{全部坏客户数}
$$

表示规则抓住了多少坏客户。

**4）排序性**

关注不同区间的坏账率是否按变量大小呈现单调趋势。排序性好，规则阈值更容易解释和调整。

**5）可解释性**

规则本身应符合业务逻辑，例如查询次数越多风险更高、逾期次数越多风险更高、信用分越低风险更高。

### 3.4.3 基于分箱的阈值分析

示例将最后一箱设为拒绝区间：

```text
最近 3 个月新型非银金融机构查询次数 > 4
```

满足条件拒绝，否则通过。

该规则表现：

- 命中率：5.01%；
- 命中客群坏账率：18.87%；
- Lift：18.87% ÷ 6.43% = 2.93；
- 坏客户召回率：14.71%（20/136）；
- 好客户误杀率：4.34%（86/1980）；
- 分箱坏账率具有明显排序性；
- 规则具有业务可解释性。

### 3.4.4 极端值检测

基本思想：高风险客群往往是异常客群，其变量取值会集中在常人分布的两端。

做法：

1. 枚举若干分位点作为候选阈值，例如 0.005、0.01、0.02、0.05、0.95、0.98、0.99、0.995；
2. 以分位点对应值作为候选阈值；
3. 逐个计算命中率、命中客群坏账率、Lift、召回率；
4. 选择命中率适中、风险提升明显的阈值。

示例中，阈值约为 4.25 时综合效果最佳：

- 命中率约 5.01%；
- 命中客群坏账率约 18.87%；
- Lift 约 2.94。

# 四、交叉表规则生成

## 4.1 交叉表的概念

交叉表是两个或两个以上变量的交叉判断。

示例变量：

- 最近 6 个月新开信贷账户数；
- 当前公积金状态。

两个变量形成**二维交叉表**，两个以上变量形成多维交叉表。本质上，交叉表是变量的"笛卡尔积"，也可以理解为结构简单、人工可控的决策树。

示例区间坏账率：

| 最近 6 个月新开信贷账户数 | 公积金状态 = -9999 | 公积金状态 = 1 | 公积金状态 = 2 |
|---|---:|---:|---:|
| (-0.001, 0.5] | 4.24% | 1.60% | 2.97% |
| (0.5, 1.5] | 12.60% | 6.12% | 13.04% |
| (1.5, 2.5] | 21.74% | 8.82% | 17.95% |
| (2.5, 28.0] | 19.18% | 12.66% | 34.00% |

## 4.2 交叉表的特点

从规则复杂度和变量维度看：

```text
单变量规则 → 二维交叉表 → 多维交叉表 → 逻辑回归评分卡
简单、维度少 ---------------------------> 复杂、维度多
```

特点：

- 比单变量规则维度更多，风险评估更精确；
- 比评分卡模型维度更少、复杂度更低；
- 开发和调优速度更快；
- 兼顾维度和复杂度，属于规则与模型之间的中间形态。

## 4.3 生成交叉表的前置条件

**条件一：先筛选预测能力较好的变量池**

从高 IV、业务合理、稳定的变量中选择交叉组合。一般原则：

- 变量来自不同风险维度；
- 变量之间相关性不宜过高；
- 组合后应带来额外风险区分能力。

**条件二：连续变量先分箱**

- 连续变量需要分箱并保证顺序性；
- 离散变量可直接作为行列；
- 缺失值和特殊值应单独处理。

**条件三：总样本和坏样本数量足够**

交叉后格子数量会快速增加。例如单变量有 4 个箱，与 3 个状态的离散变量交叉后变成 12 个格子；如果总样本和坏样本不足，每个格子可能样本过少，导致坏账率波动或无法统计。

# 五、决策树规则生成

## 5.1 决策树的概念

决策树是一组 if-then 规则的集合，自上而下按照某种度量标准不断分裂，形成树形结构。

节点类型：

- **根节点**：树的起始节点；
- **内部节点 / 分裂节点**：根据特征及阈值继续划分；
- **叶子节点 / 末端节点**：不再继续分裂，输出最终类别或数值。

决策树通过变量组合对特征空间进行非线性划分，因此属于**非线性模型**。

## 5.2 决策树的生成过程

从根节点开始：

1. 在每个分裂节点，从特征池中选择最优变量；
2. 选择该变量对应的最优阈值；
3. 将样本划分为两个或多个子集；
4. 继续向下递归分裂；
5. 达到停止条件后输出叶子节点结果。

## 5.3 决策树算法

### 5.3.1 算法分类

常见算法：

| 算法 | 任务 | 常用划分指标 | 是否二叉树 |
|---|---|---|---|
| ID3 | 分类 | 信息增益 | 不一定 |
| C4.5 | 分类 | 信息增益率 | 不一定 |
| CART | 分类、回归 | 基尼系数 / 残差平方和 | 是 |

重点介绍 CART，因为：

- 可做分类和回归；
- 二叉树计算效率较高；
- 是随机森林、GBDT 等集成树模型的基础。

### 5.3.2 CART 分类树：基尼系数

对于数据集 $D$，基尼指数：

$$
Gini(D) = \sum_{k=1}^{K} p_k(1-p_k) = 1 - \sum_{k=1}^{K} p_k^2
$$

二分类情况下：

$$
Gini(p) = 2p(1-p)
$$

含义：Gini 越小，数据纯度越高；Gini 越大，类别越混杂。

示例：

- 好坏客户各占 50%：$Gini = 2 \times 0.5 \times 0.5 = 0.5$，不纯度最大；
- 全部为好客户或全部为坏客户：$Gini = 0$，节点最纯。

按特征 $A$ 划分后的条件基尼系数：

$$
Gini(D|A) = \sum_{i=1}^{n} \frac{|D_i|}{|D|} Gini(D_i)
$$

二叉切分时：

$$
Gini(D|A) = \frac{|D_1|}{|D|} Gini(D_1) + \frac{|D_2|}{|D|} Gini(D_2)
$$

选择加权 Gini 最小的变量和切分点。

### 5.3.3 变量二分法

**连续变量**：假设变量有 $m$ 个不同取值，从小到大排列。

- 可形成 $m-1$ 个候选切分点；
- 切分点通常取相邻值的中点；
- 每个切分点将数据分为 $D_1$ 和 $D_2$；
- 计算每个切分点的加权 Gini；
- 选择最小者作为最优切分。

**离散变量**：对具有多个类别的变量进行二分。

- 取一个类别作为一组，其余类别作为另一组；
- 枚举候选类别组合；
- 计算每种划分的加权 Gini；
- 选择 Gini 最小的划分。

### 5.3.4 CART 分类树递归生成

输入：训练集、基尼系数停止阈值、最小切分样本数。输出：分类树。

递归步骤：

1. 若当前节点样本数小于阈值，或没有可用特征，则停止；
2. 计算当前节点数据集的 Gini；
3. 若 Gini 小于停止阈值，则停止；
4. 计算所有特征及候选取值对应的 Gini；
5. 选取 Gini 最小的特征 $A$ 和最优切分点 $a$；
6. 按该切分将数据划分为 $D_1$ 和 $D_2$；
7. 生成左右子节点；
8. 对左右节点重复以上步骤。

预测时：样本沿树结构进入某个叶子节点，分类结果取该叶子节点中占比最高的类别。

### 5.3.5 CART 回归树

**预测方式**：回归树的目标变量是连续值。

1. 每个输入样本落入一个叶子区域 $R_m$；
2. 该叶子节点预测值为该区域内训练样本目标值的均值；
3. 回归树可表示为：

$$
f(x) = \sum_{m=1}^{M} c_m I(x \in R_m)
$$

其中 $R_m$ 为第 $m$ 个叶子区域，$c_m$ 为该区域目标值均值。

**残差平方和（RSS）**：回归树通常使用 RSS 作为划分标准，目标是找到变量 $j$ 和切分点 $s$，使左右节点残差平方和最小：

$$
\min_{j,s} \left[
\min_{c_1} \sum_{x_i \in R_1(j,s)} (y_i - c_1)^2
+
\min_{c_2} \sum_{x_i \in R_2(j,s)} (y_i - c_2)^2
\right]
$$

RSS 越小，说明节点内样本目标值越集中，切分效果越好。

## 5.4 决策树生成规则

### 5.4.1 从叶子路径生成规则

示例：

- 样本整体坏账率：6%；
- 决策树深度：2；
- 变量包括征信、公积金、房产等。

高风险叶子路径：

```text
过去 3 个月查询机构数 > 6
且 是否有公积金 = 否
```

该叶子坏账率约 12%，因此生成拒绝规则：

```text
过去 3 个月查询机构数 > 6
AND 是否有公积金 = 否
→ 拒绝
```

否则通过。

### 5.4.2 决策树规则注意事项

**1）控制规则复杂度**

树越深，客群划分越细，但会带来：

- 训练样本过拟合；
- OOT 效果下降；
- 规则条件过多；
- 上线配置困难；
- 监控和问题定位困难；
- 运营维护成本增加。

通常建议：信贷风控中一条规则包含的变量数量一般不超过 3 个。

**2）使用统一评估指标**

与单变量和交叉表相同，综合考虑：精准率、召回率、命中率、Lift、排序性、稳定性。

**3）保证业务可解释性**

通过决策树生成的规则也必须满足业务可解释性，不能仅依赖统计结果。

## 5.5 sklearn 决策树 API

`sklearn.tree` 的两个主要方法：

```python
from sklearn import tree

tree.DecisionTreeClassifier()  # CART 分类树
tree.DecisionTreeRegressor()   # CART 回归树
```

sklearn 未直接实现 ID3 和 C4.5，主要实现的是优化后的 CART。

主要参数：

| 参数 | 含义 |
|---|---|
| `criterion` | 特征划分标准。分类常用 `gini` 或 `entropy`，默认通常为 `gini` |
| `splitter` | 节点切分方式，常用 `best` 或 `random` |
| `max_depth` | 最大树深，控制复杂度和过拟合 |
| `min_samples_split` | 内部节点继续切分所需最小样本数 |
| `min_samples_leaf` | 叶子节点最小样本数 |
| `max_features` | 每次切分考虑的最大特征数 |
| `random_state` | 随机种子，保证结果可复现 |
| `class_weight` | 类别权重，用于类别不平衡 |
| `min_impurity_decrease` | 不纯度下降达到阈值才允许切分 |
| `ccp_alpha` | 成本复杂度剪枝参数 |

决策树结果示例：每个节点展示切分条件、bad_rate、samples、value、reject_rate、recall_rate；颜色越深的叶子代表风险越高或拒绝比例越高，可从根节点到高风险叶子节点提取为规则路径。

# 六、规则泛化效果评估

## 6.1 概念

规则开发后存在两类评估：

**1）规则生成阶段的评估**：用于筛选规则，主要关注命中率、精准率、召回率、Lift、排序性、可解释性。

**2）规则筛选后的泛化评估**：用分析样本以外的数据，评估规则对业务的真实影响，主要关注逾期率、通过率、规则稳定性。既可以评估单条规则，也可以评估整个规则集。

## 6.2 分析流程

1. 选择合适的泛化样本；
2. 对规则涉及的底层变量进行回溯和加工；
3. 使用宽表变量复现规则或规则集；
4. 将规则应用于泛化样本；
5. 计算泛化样本上的效果；
6. 与分析样本结果进行对比。

重要要求：

- 泛化评估虽然是规则开发后期环节，但样本方案应提前设计；
- 变量回溯应尽量一次性完成；
- 避免规则开发完成后才发现历史数据无法复现。

## 6.3 逾期率泛化样本

泛化评估的逻辑：用历史数据推演规则，验证其对未来风险的识别能力。

时间外样本（OOT）要求：

1. 时间窗口位于分析样本之后；
2. 样本量满足统计意义，一般至少覆盖 3 个月；
3. 与分析样本采用相同的贷后表现定义；
4. 客群和整体风险水平与分析样本基本一致；
5. 按月拆分评估，观察稳定性。

示例：

```text
分析样本：12 个月
时间外 OOT：3 个月
当前时点：更晚的观测时点
```

## 6.4 逾期率评估指标

$$
命中率 = \frac{规则命中样本数}{样本总数}
$$

$$
精准率 = \frac{规则命中样本中的坏客户数}{规则命中样本数}
$$

$$
召回率 = \frac{规则命中的坏客户数}{样本总坏客户数}
$$

$$
Lift = \frac{规则命中客群坏账率}{样本整体坏账率}
$$

**逾期率下降幅度**：

$$
逾期率下降幅度 = \frac{样本整体坏账率 - 规则通过样本坏账率}{样本整体坏账率}
$$

评估方法：

- 分析样本和 OOT 分别计算上述指标；
- 比较指标变化；
- 若 OOT 指标在分析样本附近小幅波动，则泛化达标；
- 通常建议一般波动不超过 10%，严格时不超过 5%。

示例：

- 分析样本 Lift = 3；
- OOT Lift = 1：效果衰减严重，可能过拟合；
- OOT Lift 在 2.7–3.3：处于 ±10% 范围，泛化能力较好。

## 6.5 通过率效果评估

逾期率评估需要足够长的贷后表现，因此 OOT 时间窗口往往距离当前较远，客群可能发生变化。通过率评估不需要贷后表现，可以使用距离当前更近的新鲜样本。

方法：

1. 选择近期 3 个月或其他新鲜申请样本；
2. 回溯规则变量；
3. 分别计算规则应用前后的通过率；
4. 评估规则对业务规模的影响。

注意：

- 通过率评估样本也需要提前完成变量回溯；
- 通常与逾期率 OOT 样本分开设计；
- 通过率指标可使用 `1 - 命中率`；
- 通过率受时间、渠道、产品和策略变化影响，不能只看总体数值，还需分析变量分布和客群结构。

# 七、规则集的三种结构

## 7.1 规则集定义

规则集是一系列规则的集合，在策略中通常对应一个决策节点。

示例规则集：

- 准入规则集；
- 黑名单规则集；
- 反欺诈规则集；
- 征信规则集；
- 多头共债规则集。

同一规则集可以包含：

- 不同数据源的规则；
- 人工规则；
- 单变量规则；
- 交叉表规则；
- 决策树规则；
- 模型分数规则。

## 7.2 三种结构

规则集主要有三种结构：串行结构、并行结构、串行与并行组合结构。

## 7.3 串行结构

串行结构按照固定顺序依次执行规则。

特点：

1. 某条规则一旦命中并产生终止决策，后续规则不再执行；
2. 每条规则承接上一条规则过滤后的剩余流量；
3. 各规则命中率是基于不同剩余客群计算的；
4. 通过客户需要未命中所有规则；
5. 规则顺序通常需要设置优先级；
6. 形成漏斗式筛选，高成本数据可放在后面，降低整体调用成本。

示例：

```text
规则1 → 规则2 → 规则3 → … → 规则N
             ↓
            拒绝
```

顺序设计示例：先使用内部黑名单，未命中后再调用外部付费黑名单，可以节约外部数据调用成本。

## 7.4 并行结构

并行结构中的规则相互独立、全部执行。

特点：

1. 没有前后顺序；
2. 每条规则都输出是否命中；
3. 同一客户可以命中多条规则；
4. 只要命中其中一条即可拒绝；
5. 所有规则均未命中才通过。

## 7.5 串行与并行的比较

| 对比项 | 串行规则集 | 并行规则集 |
|---|---|---|
| 执行效率 | 规则很多时效率较高，命中后可提前终止 | 规则很多时全部执行，效率较低 |
| 数据获取 | 部分规则不执行，无法获得全部规则命中表现 | 全部规则执行，可获得完整单一命中和组合命中数据 |
| 监控分析 | 未执行规则缺少命中数据，不利于监控和迭代 | 便于分析单一命中、交叉命中和相互覆盖 |
| 使用场景 | 有明确优先级、成本控制或前置拦截场景 | 规则无优先级，需要贷后监控和调优分析 |

实际策略中常采用串并行组合：

- 外层按规则集串行；
- 规则集内部采用并行；
- 关键强规则允许提前终止；
- 其余规则保留完整命中日志。

# 八、贷前策略规则集线下性能测试

## 8.1 规则集分析流程

贷前策略规则集的完整分析流程：

**01 规则挖掘**：单变量规则、二维交叉规则、多维决策树规则。

**02 规则评估**：计算命中率、召回率、精准率、Lift、排序性、稳定性，筛选候选规则。

**03 规则集线下性能测试**：将候选规则组成规则集，评估综合命中、整体风险、规则间覆盖、单一命中、组合命中。

**04 规则集线上效果监控**：定期监控单条规则命中率、规则组合命中率、通过率、坏账率、客群结构。

**05 规则调优**：根据监控结果进行 A 类调优、D 类调优、阈值调整、规则增删、顺序和结构调整。

## 8.2 三个核心指标

1. **综合命中率**：表示规则集整体拒绝的客户比例；
2. **整体坏账率**：表示规则集命中客群中的坏客户占比，反映规则集整体风险识别效果；
3. **相互覆盖率**：反映规则之间的重叠情况，以及单条规则的独立贡献。

## 8.3 综合命中率

综合命中率是规则集作为整体的最终命中率。

注意：

- 不等于各规则命中率简单相加；
- 原因是客户可能同时命中多条规则；
- 规则集命中条件取决于决策逻辑（OR / AND、最少命中条数）。

示例：

**至少命中 1 条即拒绝**

- 规则 1 命中率：3/8 = 37.5%；
- 规则 2 命中率：4/8 = 50.0%；
- 规则集命中率：5/8 = 62.5%。

**至少命中 2 条才拒绝**

- 规则集命中率：2/8 = 25.0%。

## 8.4 整体坏账率

整体坏账率针对规则集整体计算：

1. 根据单条规则命中结果生成规则集命中标记；
2. 满足规则集拒绝条件的客户记为命中；
3. 统计规则集命中客户中的坏客户占比。

示例（至少命中 1 条即拒绝）：

| 对象 | 命中率 | 命中客群坏账率 |
|---|---:|---:|
| 规则 1 | 3/8 = 37.5% | 2/3 = 66.7% |
| 规则 2 | 4/8 = 50.0% | 3/4 = 75.0% |
| 规则集 | 5/8 = 62.5% | 4/5 = 80.0% |

规则集整体坏账率不等于单规则坏账率平均值。

## 8.5 相互覆盖率与单一命中率

**相互覆盖率**：统计一条规则的命中是否被其他规则覆盖。若某规则命中客户全部被其他规则覆盖，则：

- 删除该规则后，规则集命中结果不变；
- 该规则缺乏独立贡献；
- 可以考虑删除或降级。

**单一命中率**：表示只命中该规则、未命中其他规则的客户比例。

示例：

| 规则 | 命中率 | 单一命中率 |
|---|---:|---:|
| 规则 1 | 3/8 = 37.5% | 0% |
| 规则 2 | 4/8 = 50.0% | 1/8 = 12.5% |
| 规则 3 | 4/8 = 50.0% | 1/8 = 12.5% |

结论：

1. 规则 1 的命中全部被规则 3 覆盖，可以优先删除规则 1；
2. 删除规则 1 后，再重新计算规则 2、规则 3 的单一命中率；
3. 相互覆盖分析需要按顺序迭代，不能一次性静态判断。

## 8.6 案例实操数据

示例案例字段：

| 变量 | 含义 | 分布类型 | 数据类型 |
|---|---|---|---|
| ID | 客户 ID | 离散型 | char |
| TARGET | 好坏标签，0/1 = 好/坏 | 离散型 | int |

# 九、核心方法总结

## 9.1 规则开发的完整闭环

```text
风险识别 / 变量开发
        ↓
样本与标签定义
        ↓
变量初筛
        ↓
分箱、WOE、IV
        ↓
单变量 / 交叉表 / 决策树规则生成
        ↓
命中率、坏账率、召回率、Lift、解释性评估
        ↓
时间外样本泛化验证
        ↓
规则集组合与线下性能测试
        ↓
上线验证、监控与调优
```

## 9.2 三类规则生成方法的对比

| 方法 | 优点 | 局限 | 适用场景 |
|---|---|---|---|
| 单变量规则 | 简单、透明、上线快 | 风险区分较粗 | 明确的单一风险点 |
| 交叉表规则 | 解释性好、区分更细 | 维度增加后样本要求高 | 两到三个互补变量组合 |
| 决策树规则 | 自动寻找多变量组合 | 易过拟合、规则可能复杂 | 从大量变量中发现组合风险 |

## 9.3 规则筛选原则

一条值得保留的规则通常应满足：

- 命中率适中；
- 拒绝组坏账率显著高于总体；
- Lift 较高；
- 坏客户召回率有实际贡献；
- 对好客户损失可控；
- 分箱排序合理；
- 跨时间表现稳定；
- 业务解释清晰；
- 与现有规则重复度较低；
- 线上变量可稳定获取和计算。

## 9.4 规则不是一次性产物

规则需要持续监控和迭代，主要原因包括：

- 客群发生变化；
- 市场环境发生变化；
- 数据源和变量口径变化；
- 产品政策变化；
- 欺诈模式变化；
- 规则之间的覆盖关系变化。

因此，成熟的规则体系应具备：

- 版本管理；
- 线上监控；
- 异常预警；
- 定期复盘；
- OOT 验证；
- 阈值调整；
- 冗余规则清理；
- 策略效果归因。

# 附录：核心公式与指标速查

## A.1 单规则指标

$$
命中率 = \frac{命中客户数}{总客户数}
$$

$$
精准率 = \frac{命中客户中的坏客户数}{命中客户数}
$$

$$
召回率 = \frac{命中的坏客户数}{全部坏客户数}
$$

$$
Lift = \frac{命中客群坏账率}{整体坏账率}
$$

## A.2 WOE 与 IV

$$
WOE_i = \ln\left(\frac{Bad_i / Bad_T}{Good_i / Good_T}\right)
$$

$$
IV_i = \left(\frac{Bad_i}{Bad_T} - \frac{Good_i}{Good_T}\right) \times WOE_i
$$

$$
IV = \sum_i IV_i
$$

## A.3 基尼指数

$$
Gini(D) = 1 - \sum_{k=1}^{K} p_k^2
$$

二分类：$Gini(p) = 2p(1-p)$

划分后：$Gini(D|A) = \sum_i \frac{|D_i|}{|D|} Gini(D_i)$

## A.4 回归树 RSS

$$
\min_{j,s} \left[
\min_{c_1} \sum_{x_i \in R_1(j,s)} (y_i - c_1)^2
+
\min_{c_2} \sum_{x_i \in R_2(j,s)} (y_i - c_2)^2
\right]
$$

## A.5 规则泛化指标

$$
逾期率下降幅度 = \frac{整体坏账率 - 规则通过样本坏账率}{整体坏账率}
$$

推荐观察：

- 分析样本与 OOT 指标变化；
- 月度稳定性；
- 客群漂移；
- 变量分布变化；
- 命中率与 Lift 的同步变化；
- 通过率影响；
- 规则间覆盖和独立贡献。
