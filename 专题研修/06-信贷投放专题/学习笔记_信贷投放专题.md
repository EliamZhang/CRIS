## 单元 0：整条链路总览 ✅（2026-09-06 完成）

### 1. 七个阶段：一条链，七个问题

七个阶段依次回答七个问题：① 平台机制——平台为什么把广告展示给这个人？② 漏斗与回传——平台带来的用户走到了信贷流程哪一步？③ 归因与 Cohort——这笔转化算谁的？④ Quality/Value——什么样的转化才真正有价值？⑤ 四大杠杆——改人群、素材、出价还是预算？⑥ 因果实验——指标变好真的是广告造成的吗？⑦ 风险收益预算——下一块钱应该投到哪里？

**前四步是"信号工程"**：理解平台怎么要信号 → 生产信号 → 定口径 → 升级信号；**后三步是"动手—验证—决策"**：调杠杆 → 验证因果 → 按利润分预算。

**为什么要按这个顺序排列？** 两个局部的先后关系最能说明问题：

- ② 必须在 ③ 之前——先有凭证，再谈记账。归因是给"已发生的转化"记账的规则，如果漏斗没有打通、事件没有回传，后端发生了什么你根本看不到，归因规则再精细也是垃圾进、垃圾出；
- ④ 必须在 ⑤ 之前——先换目标函数，再动手操作。平台只优化你回传的目标：你回传"申请提交"，平台就找会申请的人，这时候调人群、换素材、改出价，平台仍然在"申请提交"这个目标下找人。只有先把回传目标升级为价值信号，四大杠杆才能用在正确方向上；而且 ⑤ 中最有力的两个出价方式（tROAS、Max Conversion Value）本身就依赖 ④ 提供的差异化 value。

### 2. 三个易混概念：归因 / 增量 / 收益

- **归因（Attribution）**回答"这笔已发生的转化记给哪个渠道"，是记账规则问题，典型方法有 Last click、view-through、MMP 归因；
- **增量（Incrementality）**回答"如果不投广告，这笔转化是否仍会发生"，是因果问题，典型方法有随机 Holdout、Conversion Lift、Geo Test；
- **收益（Profitability）**回答"广告带来的增量业务扣掉风险和成本后赚不赚钱"，是经济问题，典型方法是 Risk-adjusted LTV、增量 ROI、边际 ROI。

**场景走查：一位老客户，一笔放款，三个口径。** 一位老客户本来就打算这周借款，周一刷到你的广告、点击、提交申请、最终放款成功：

- 归因口径：平台按 last click 把这次放款记到广告头上，平台报表 +1 笔转化，ROAS 很漂亮——但只是"记账规则"下的数字；
- 增量口径：如果这周不投广告，他照样会去借——这笔放款的增量 = 0；
- 收益口径：即使某笔转化确是真增量，还要看放款后的 DPD30 高不高、利息贡献扣掉资金成本和信用损失后剩多少——可能为负。

三个概念的用途也不同：归因做渠道对账与口径统一，增量做因果判断，收益做预算决策。最终预算必须三者同时参考：只看归因会被"抢功"的渠道骗，只看增量不知道赚不赚钱，只看收益算不出真实增量就无从归因。

**三个数字的大小关系。** 同一投放按三个口径衡量，数字会依次收紧：归因转化 ≥ 增量转化（归因里混着"不投也会发生"的非增量部分）；风险调整利润 = 增量价值 − 各项风险成本 − 媒体花费，是净额、可能为负，所以最小。严格说转化数是"个数"、利润是"金额"，不能直接比大小——这个排序真正想说的是口径纪律：以后看任何投放报表，先问"这是哪个口径的数字"。

另外注意：风险调整利润不是"收入"，是**净贡献**。收入是毛的（利息收进来多少），净贡献是扣完所有成本后剩多少。利润瀑布里"利息及合规费用收入"那一行才是收入，瀑布底部的才是利润。

### 3. ROAS：平台报表里的数字为什么不等于利润

**ROAS（Return on Ad Spend，广告支出回报率）= 广告带来的转化收入 ÷ 广告花费**，回答"每花 1 元广告费带回多少毛收入"。它与 ROI 的区别：ROAS 分子是毛收入、只扣媒体费；ROI 是净利润口径、扣全部成本——所以 ROAS 高不代表赚钱（毛利率低于 50% 时，ROAS 2 也可能亏）。

"平台 ROAS ≠ 真实利润"有三层原因：

1. **归因口径**：平台 ROAS 的转化是归因口径，含"不投广告也会发生"的非增量转化；
2. **value 口径**：分子是回传的 value，若把放款本金当收入会严重失真——本金是借出的钱，不是赚的钱；
3. **成本口径**：ROAS 只扣媒体费，不扣资金成本、信用损失、催收成本等信贷特有成本。

顺带一提 **tROAS（目标 ROAS 出价）**：告诉平台"每 1 元广告费至少要带回 X 元价值"，平台在回报约束下最大化价值。它要求回传 value 稳定且与真实利润同向，否则"value 错误会放大偏差"。

## 单元 1：平台机制——平台到底在帮你找什么人？🔄（2026-09-06 开课）

### 1. 核心认知：平台在竞价中挑"预期价值更高"的展示机会

平台不是"帮你找最多点击的人"。它是在给定目标、预算、出价和约束后，预测每一次展示的结果，然后在竞价中挑选**预期价值更高**的展示机会：

```text
一次展示的预期价值 ≈ 预估行动概率 × 转化价值 × 出价/目标约束 × 广告质量修正
```

配合 01 实战合集第四篇《竞价底层逻辑》的补充，这个公式就活了：不管你按什么方式出价（CPM/CPC/CPA），平台都会统一换算成 **eCPM**（每千次展示平台预期赚到的钱）来排序：

```text
eCPM ≈ 出价 × 预估点击率 × 预估转化率 × 1000
```

所以**出价低不一定输**——素材点击率高、落地页转化好，eCPM 依然能压过出价更高的竞品。Google 的 Ad Rank（出价 × 质量分）同理：质量分高，等于给你"打折"。这就是 01 合集说的"以小博大"空间。

**这个预期价值是谁计算的？** 平台。广告主无法直接查看或设定它，只能提供"原料"：出价/目标约束（唯一完全自己说了算的因子）、素材（影响预估行动率与质量分）、回传信号（影响转化价值与平台对广告的转化预估）；预估行动概率与质量修正都是平台模型的输出。这决定了广告主能做和不能做的事：不能直接告诉平台"这次展示对我值多少"，不能看到平台对每次展示的估价，只能通过调出价、换素材、改回传信号间接影响它。CPM 是你"愿意付"的价格，eCPM 是平台"实际能赚"的价格——后者才是平台真正关心的。

### 2. 预期价值怎么用：平台侧与广告主侧

**平台侧：拍卖系统的三个用途。** 预期价值是平台拍卖系统的决策变量：

1. **决定谁赢**——每次展示机会出现（如用户刷信息流刷到一个广告位），平台把所有有资格参竞的广告拉出来，为每个广告计算这次展示的预期价值（统一换算成 eCPM）并排序，**最高的赢得展示**。这不是在和人竞争，而是在和数据竞争；
2. **决定赢家付多少**——扣费以预期价值为基准：GSP（Google）下实际 CPC = 下一名的 Ad Rank ÷ 自己的质量分 + 最小增量，付的是"刚好压过第二名"的价格；VCG（Meta）下支付挤掉其他广告主造成的价值损失；一价拍卖支付自己的出价。预期价值不仅决定赢不赢，还决定赢的那一下贵不贵；
3. **决定平台替你怎么花预算**——oCPX（tCPA/tROAS）模式下，平台以你的目标为约束**自动出价**：用预估行动率 × 转化价值判断"这次展示买下来转化成本大概多少"，只有预估结果符合目标的展示机会才参竞，并做 Pacing 把预算花在预期价值最高的机会上、平滑花完。预期价值是自动出价引擎的燃料。

完整闭环：展示机会出现 → 平台计算各广告预期价值并排序 → 最高者赢得展示并按规则扣费 → 用户若转化，回传事件成为训练数据 → 平台更新对"这类人"的预估 → 下一次同类展示，给该广告更准的估价、更积极的出价。因此原料（出价/素材/回传信号）质量直接决定平台"给不给你量、以什么价给你量"——这也是"tCPA 设过低花不出去"的原理：平台算下来几乎每次展示的预估成本都超目标，就没有机会替你参竞。

**广告主侧：体检表。** 参考方式不是去"读"它（黑箱，读不到），而是去"用"它的公式——它是一张体检表，四个因子正好对应广告主能动的四块原料，指标异常时依次排查：

| 因子 | 对应杠杆 | 症状 → 检查方向 |
|------|---------|----------------|
| 预估行动率 | 素材、人群 | 花不出去、量少 → 素材点击率差、人群不匹配 |
| 转化价值 | 回传信号设计 | CPA 好看但 DPD 差 → 回传目标太浅、value 失真 |
| 出价 | 出价策略 | 量长期上不去 → 出价相对市场水平偏低 |
| 质量修正 | 素材体验、负反馈 | 展示机会少、成本上升 → 负反馈多、素材体验差 |

两点引申：① 竞争的维度是"数据"而非"人"——谁的素材+人群+信号组合能让平台算出更高的预期价值，谁就赢，所以优化原料（素材、回传）通常比单纯加价更可持续（"以小博大"）；② 反向监控平台——"转化价值"是唯一能让平台看见你利润的窗口，若回传正确，平台的估价排序应逐步向你的利润排序靠拢；若平台给量方向与内部质量排序长期矛盾，说明回传信号有问题（阶段②④伏笔）。

**后台可见性：只能看到分档摘要。** 广告主能看到的是"分档摘要"，不是逐次展示的实时估价。以 Google 为例：质量得分（1-10 分档，由预期点击率、广告相关性、落地页体验三项评级构成）、竞价洞察（展示份额、和谁竞争、输给谁、因排名/预算丢失的份额）、页首/首页出价参考。看不到的是每次展示的实时预期价值数值、Ad Rank 具体值、pCTR/pCVR 精确值、竞品的 eCPM。这些可见信号正是"体检表"的现实版本：质量得分 ≈ 质量因子摘要，预期点击率评级 ≈ pCTR 摘要，展示份额丢失（排名）≈ 排序竞争的反馈，页首出价参考 ≈ 出价够不够的提示。趋势上可见性在收缩（Smart Bidding、PMax 越来越黑箱，Meta 只给粗略的相关度诊断排名），但摘要信号对诊断已够用。

### 3. 账户层级：指标变了，去哪一层找原因

| 层级 | 定义什么 |
|------|---------|
| Campaign | 业务目标、预算方式、地域——大方向 |
| Ad set / Ad group | 人群、版位、出价、**优化事件**——中间层 |
| Ad / Creative | 图片、视频、标题、文案、落地页——素材层 |
| Conversion event | **平台真正被要求寻找的结果**（如申请提交、审批通过、放款） |

本单元的过关要求是：任何一个指标变化，你能说出应该在哪一层定位和调整。

### 4. 竞价与交付的六个关键词

- **Auction（竞价）**：每一次展示都是一场拍卖，多个广告竞争这个机会；
- **Bid（出价）**：你愿意为目标结果付多少，或希望达到什么 CPA/ROAS；
- **Predicted action rate（预估行动率）**：平台预测"这个人完成目标动作"的概率——这就是 eCPM 公式里的 pCTR × pCVR；
- **Ad quality（广告质量）**：素材体验、负反馈、相关性等质量信号；
- **Pacing（预算节奏）**：平台如何在一天或整个周期内平滑花完你的预算；
- **Saturation（饱和）**：预算增加后优质流量逐渐耗尽，边际成本上升——它是阶段⑦"边际 ROI"埋下的伏笔。

### 5. 优化目标与出价方式：你让平台去哪类人里找人

综述 2.3 的六种方式，本质不是"哪种更好"，而是**"你给平台下的找人指令"**：

| 方式 | 平台倾向找 | 适合阶段 | 主要风险 |
|------|-----------|---------|---------|
| CPM / Reach | 便宜展示 | 品牌曝光 | 与信贷转化较远 |
| CPC / Traffic | 容易点击的人 | 冷启动、落地页测试 | 低意向点击 |
| Max Conversions | 尽量多的目标事件 | 已有稳定转化回传 | 只追数量，不区分价值 |
| tCPA | 目标成本附近的转化 | 转化量较稳定 | 目标过紧会限制交付 |
| Max Conversion Value | 最大化总转化价值 | 已能回传差异化 value | value 错误会放大偏差 |
| tROAS | 回报约束下最大化价值 | 价值回传稳定且量足够 | 延迟、稀疏和价值漂移影响学习 |

这里呼应单元 0 的主线：**目标定在"申请提交"，平台就找会提交申请的人；目标定在"价值"，平台才有机会找有价值的人。** 01 合集把 oCPX（tCPA 这类）的本质概括得很准：广告主表达"我想要什么成本"，平台用算法去实现这个成本目标。

#### 回传的 value 设计（单元 4 完整展开）

回传事件不只是告诉平台"发生了一次转化"，还可以附带数值——value 设计就是决定"每次回传的转化事件附带一个什么数值"，让平台按这个数值理解"什么样的用户更值钱"。如果不做设计会有三重后果：不带 value，平台对所有转化一视同仁、只追数量；填放款本金，平台会学成"贷款额越大越值钱"（但本金是借出的钱，不是赚的钱）；填未来才知道的信息（如"最终没逾期"），就是标签泄漏——申请提交那一刻根本算不出来，平台学到的东西在真实投放时无法复现。

设计的原则：value 与长期利润同向（value 越高，长期平均利润应越高）；只用事件发生时可得的信息；不把媒体成本算进 value（否则出价越高 value 越低，目标自我循环）；负值用 max(0,·) 或分档处理；防止极端大值支配平台学习。

示例：申请 X 的放款概率 50%、预期利息 AUD 200、资金与运营成本 40、ECL+欺诈 80，value = 50%×(200−40−80) = 40；申请 Y 的放款概率 35%、预期利息 300、成本 50、ECL+欺诈 30，value = 35%×(300−50−30) = 77。回传时 X 带 40、Y 带 77，平台学到"Y 类人价值接近 X 的两倍"，在 Max Conversion Value 或 tROAS 模式下就会给 Y 类用户更多竞价机会——尽管 Y 的申请概率更低。

### 6. 学习期与信号质量：平台怎么"学会"找人

平台的学习 = 反复观察"什么样的人最终发生了目标事件"。它学得好不好，取决于你喂的信号：

- **事件量**：太少，模型区分不了人群；
- **事件延迟**：申请实时发生，但放款数天、逾期数月才知道——深层事件天然慢；
- **事件稳定性**：定义频繁变化，平台学到的目标会漂移；
- **事件可区分性**：所有事件 value 都相同，就无法做价值排序；
- **大幅频繁修改**：交付重新探索，短期波动变大。

综述给了一句很关键的话：**不要机械套用某个平台的固定"最低转化数"，真正应该检查的是——事件是否足够多、延迟是否稳定、标签是否与长期利润同向。**

### 7. 信贷案例：优化"申请" vs 优化"优质申请"

```text
单个申请的预期价值 = 放款概率 × 每笔放款的风险调整贡献
```

| 用户类型 | 申请概率 | 放款概率 | DPD30 | 单个申请预期价值 |
|---|---:|---:|---:|---:|
| A：高意向、低质量 | 20% | 5% | 25% | AUD 4 |
| B：中意向、高质量 | 10% | 35% | 5% | AUD 22 |

如果目标设为"申请提交"，平台会偏向 A——因为 A 的申请概率更高，喂给平台的目标信号更"多"。只有回传"风险调整价值"这类差异化 value，平台才有机会把 B 的流量抬起来。

这正好印证 01 合集第一篇给信贷投放下的定义：**在风控约束下，以可控成本精准获取"能通过审核、愿意借款、按时还款、持续复借"的用户。** 投放和风控，在这里第一次握手。

**主线：平台只会优化你提供给它的目标，不会自动理解你的信贷利润。**
