# 一、规则的认识和类型（P001–P012）

## 1. 规则的概念（P003–P004）

**规则是基于变量（特征）的一系列判断条件组合。**

规则成立的前提：

1. 规则基于特征变量产生，数据和变量是制定规则的先决条件。
2. 规则可以是一个判断条件，也可以是多个判断条件的组合。
3. 判断结果通常对应业务决策，如通过、拒绝、转人工审核等。

示例：

- 单变量规则：`年龄 > 60`
- 多条件规则：`性别 = 男 且 年龄 > 60`

逻辑结构可分为三层：

- **数据层**：年龄、性别、查询次数、逾期次数等变量。
- **规则层**：对变量设置判断条件。
- **决策层**：规则满足后输出拒绝或通过。

---

## 2. 规则的作用（P005）

规则的判断具有**筛选作用**，可以按照某些风险维度对客户进行细分。

在信贷风控中，规则主要用于：

- 识别不同风险水平的人群；
- 拒绝高风险人群；
- 通过低风险人群；
- 规避潜在信用风险。

这类用于风险识别和客户筛选的规则，通常称为**风控规则**。

示例：

- 特征变量：过去 12 个月的逾期次数。
- 风控规则：`逾期次数 > 3`。
- 决策结果：
  - 满足条件：拒绝；
  - 不满足条件：通过。
- 样本表现：
  - 被拒绝客群逾期率约 8%；
  - 通过客群逾期率约 2%。

---

## 3. 规则与策略的关系（P006）

在信贷风控中：

- **策略**是对模型和规则的综合应用，是整个决策流程的组织者和管理者。
- **规则和模型都是策略的工具**。

典型贷前授信审批流程：

```text
客户申请 → 规则判断 → 模型评估 → 决策结果
                    ↑
                   数据
```

策略需要决定：

- 使用哪些数据；
- 使用哪些规则和模型；
- 阈值设为多少；
- 规则和模型的调用顺序；
- 规则部署在哪个决策节点；
- 命中后执行拒绝、通过还是转人工。

规则只负责自身的风险识别能力，而整个决策编排属于策略层。

---

## 4. 规则的特点（P007）

与模型相比，规则具有以下特点：

1. **可识别特定风险**：适合针对明确的风险场景进行拦截。
2. **可解释性更好**：判断依据清晰、直接。
3. **灵活性更高**：可以根据风险变化快速调整阈值或条件。

课程中的对比：

- 模型：基于大量特征，利用逻辑回归、机器学习、深度学习等复杂算法，输出一个概率或分数。
- 规则：通常是对单个变量或少量变量进行条件判断。
- 可将模型理解为“一条复杂的规则”。

---

## 5. 规则的分类（P008–P012）

规则可以从三个维度分类：

- 数据维度；
- 策略维度；
- 强弱维度。

### 5.1 数据维度（P009）

数据主要来源于征信报告和第三方数据源。征信报告通常通过人行或征信接口获取，第三方数据则通过与相关数据机构对接获取。

#### 1）征信类规则

基于征信报告衍生的风险判断规则，例如：

- 征信查询次数；
- 历史逾期次数；
- 当前逾期状态；
- 信用账户数量。

#### 2）多头类规则

从征信报告和第三方数据中获取多头借贷行为，例如：

- 多平台申请次数；
- 多机构借款数量；
- 近 1/3/6/12 个月多头行为。

#### 3）欺诈类规则

依赖第三方数据识别疑似欺诈行为，例如欺诈名单、团伙关联、异常设备或异常联系人。

#### 4）运营商类规则

通过通信运营商数据评估风险，例如：

- 手机号在网时长；
- 运营商逾期或欠费；
- 通话活跃度；
- 联系人稳定性。

#### 5）司法类规则

通过司法数据评估风险，例如：

- 被执行信息；
- 法院涉诉；
- 限高；
- 失信记录。

#### 6）设备类规则

通过 SDK 获取设备数据，例如：

- APP List；
- GPS；
- IP；
- 设备型号；
- 系统版本；
- 模拟器、Root、越狱等状态。

#### 7）消费类规则

通过银行卡消费和支付数据评估：

- 经济能力；
- 消费稳定性；
- 风险消费行为；
- 资金紧张程度。

---

### 5.2 策略维度（P010）

#### 1）准入规则

年龄、职业、地域等基础限制，通常依据公司监管要求和产品政策制定。

#### 2）黑名单规则

包括内部和外部黑名单，可细分为：

- 逾期类；
- 法院类；
- 限高类；
- 欺诈类；
- 内部拒绝名单。

黑名单客户通常属于风险较高人群。

#### 3）反欺诈规则

针对个人欺诈和团伙欺诈，常用：

- 设备信息；
- 通讯录；
- 地址定位；
- 埋点信息；
- 行为轨迹；
- 关联网络。

#### 4）身份检验规则

用于校验：

- 身份证三要素一致性；
- 在网状态；
- 联系人号码状态；
- 实名信息一致性。

#### 5）多头共债规则

识别借款人的多头借贷和共债行为，主要来源于征信和第三方数据。

#### 6）评分规则

将模型输出映射为规则判断。例如：

- 综合评分；
- 欺诈分；
- 信用分；
- 消费分。

评分本身可以作为一条效果较强的规则。

---

### 5.3 强弱维度（P011）

#### 强规则 / 硬规则（Hard Check）

特点：

- 条件设置严格；
- 命中后通常代表高风险；
- 一般不轻易调整；
- 常直接拒绝。

示例：

- 历史逾期次数超过 10 次；
- 命中黑名单；
- 命中强欺诈规则；
- 身份核验严重异常。

#### 弱规则 / 软规则（Soft Check）

特点：

- 条件更柔和、更灵活；
- 多为连续数值变量；
- 常用于信用风险评估；
- 阈值需要随客群风险变化持续调整；
- 是策略分析人员日常调优的重点。

示例：

- 信用分越低，风险越高；
- 多头申请次数过高；
- 消费或设备类风险变量异常。

---

### 5.4 设备规则案例（P012）

课程展示了一组手机厂商基于设备数据制定的规则，字段主要包括：

| 规则方向 | 变量示例 | 规则含义或阈值示例 |
|---|---|---|
| 设备信息 | 是否为样机 | 设备是否为样机，强规则 |
| 设备信息 | 手机设备首次发布时间距今月份 | 设备过旧，例如超过 36 个月 |
| 设备使用情况 | 开机天数 | 设备开机天数过短或过长 |
| 设备使用情况 | 沉默天数 | 设备长期未使用 |
| 设备使用情况 | 上月使用移动流量 | 流量极低，例如低于约 30MB |
| 设备使用情况 | 移动流量能力 | 网络或流量能力异常 |
| 设备使用情况 | 用户体验改进计划开关状态 | 状态异常或关闭 |
| 设备使用情况 | 设备登录过的账号数 | 账号数过多，例如大于 5 个 |
| 设备信息 | EMUI/系统版本号 | 系统版本明显低于主流版本 |
| 设备使用情况 | 常用联网方式 | 仅使用 2G 等异常情况 |

| APP 信息 | 30 天内新安装 APP 记录 | 新装 APP 过多，例如多于 10 个 |
| APP 信息 | 30 天内 APP 使用次数 | 使用次数过少，例如少于 100 次 |

# 二、规则分析全流程（P013–P017）

## 1. 规则全流程（P014）

规则完整流程包含两大模块：

### 模块 A：规则离线开发和评估

人工规则路径：

```text
风险识别 → 人工规则 → 变量开发 → 样本选取 → 效果评估
```

量化规则路径：

```text
变量开发 → 样本选取 → 量化规则 → 效果评估
```

### 模块 B：规则上线验证和监控

```text
规则上线 → 规则验证 → 规则监控 → 规则调整 → 重新上线
```

这是一个持续迭代的闭环。

---

## 2. 人工规则与量化规则（P015–P016）

### 2.1 人工制定规则

人工规则通常先明确风险目标，再开发对应变量。

流程：

```text
风险识别 → 明确规则目标 → 变量开发 → 样本选择 → 效果评估
```

优点：

- 风险目标明确；
- 业务解释性强；
- 开发速度相对快。

不足：

- 风险覆盖可能不全面；
- 容易依赖经验；
- 对长尾风险的识别能力有限。

### 2.2 量化制定规则

量化规则通常先批量开发变量，再通过数据分析筛选。

流程：

```text
变量开发 → 样本选取 → 统计分析与筛选 → 生成量化规则 → 效果评估
```

四个核心步骤：

1. **变量开发**：对底层数据进行抽象和关联，衍生多维度高级变量。
2. **样本选取**：根据目标定义选取合适样本，定义目标变量，划分训练集、测试集或时间外样本。
3. **量化规则**：
   - 通过 WOE/IV、区间坏账率排序、业务解释性筛选变量；
   - 结合 Lift 制定阈值；
   - 常见形式包括单一规则、交叉表、决策树。
4. **效果评估**：
   - 在 OOT 样本（有贷后表现）中评估风险效果；
   - 在授信样本（尚无贷后表现）中评估通过率影响。

人工规则和量化规则并非互斥，实际业务中通常组合使用。

---

## 3. 规则上线、验证、监控和调整（P017）

### 3.1 规则上线

将完成离线评估的规则配置到决策引擎，并发布到生产环境。

### 3.2 规则验证

验证内容包括：

- 线上配置是否正确；
- AB 测试分流比例是否正确；
- 线上规则命中率是否与线下测算接近；
- 字段和阈值是否存在偏差；
- 决策结果是否符合预期。

### 3.3 规则监控

按日、周、月持续监控：

- 命中率；
- 通过率；
- 坏账率；
- Lift；
- 客群结构；
- 数据稳定性。

出现异常时需要及时排查。

### 3.4 规则调整

根据贷后表现、客群变化和业务目标调整：

- 阈值；
- 规则条件；
- 规则顺序；
- 规则启停；
- 规则集组合方式。

# 三、单变量规则生成（P018–P038）

## 1. 整体步骤（P019–P020）

单变量规则生成一般有三个步骤：

1. 对变量进行描述性统计分析，完成变量初筛；
2. 对保留变量进行分箱，计算统计量和 IV，再次筛选；
3. 基于分箱 IV 分析或极端值检测制定规则阈值。

---

## 2. 变量初筛（P021–P023）

### 2.1 为什么要进行变量筛选（P022）

当变量数量达到几千个时，不可能全部用于规则开发，原因包括：

- 变量效果有好有坏；
- 变量之间可能重复或高度相关；
- 规则过多会增加不稳定性；
- 规则过多会增加开发、配置、监控和维护成本。

初筛主要计算：

- 缺失率；
- 众数占比；
- 唯一值数量；
- 均值；
- 最大值；
- 最小值；
- 标准差；
- 数据类型。

对不符合要求的变量进行第一轮删除，以降低后续二次筛选压力。

课程示例：

| 变量 | 含义 | 缺失率 | 众数占比 | 平均值 | 最大值 | 最小值 | 标准差 |
|---|---|---:|---:|---:|---:|---:|---:|
| A | 现行消费贷款机构数 | 5% | 2% | 2.5 | 8 | 0 | 1 |
| B | 近 12 个月旅游出行次数 | 60% | 90% | 0.1 | 1 | 0 | 0 |
| C | 月均夜间短信数 | 10% | 5% | 3 | 50 | 0 | 1.5 |
| D | 同 WIFI 地址一个月出现贷款次数 | 8% | 6% | 2 | 15 | 0 | 0.5 |

变量 B 的缺失率和众数占比过高，应优先剔除。

### 2.2 变量初筛代码逻辑（P023）

截图中的代码用于批量输出每个变量的基础统计信息。整理后的等价逻辑如下：

```python
import pandas as pd

def simple_statistics(df: pd.DataFrame) -> pd.DataFrame:
    rows = []

    for col in df.columns:
        s = df[col]

        rows.append(
            {
                "Feature": col,
                "Unique_values": s.nunique(dropna=False),
                "Percentage_of_null": s.isna().mean() * 100,
                "Percentage_of_999": (s == 999).mean() * 100,
                "Max_value_rate": (
                    s.value_counts(dropna=False, normalize=True).iloc[0] * 100
                    if len(s) else 0
                ),
                "Type": str(s.dtype),
            }
        )

    return pd.DataFrame(rows)
```

常见初筛规则：

- 缺失率过高；
- 众数占比过高；
- 单一值变量；
- 唯一值数量过少；
- 异常编码占比过高；
- 变量含义不明确；
- 数据稳定性差。

## 3. 变量分箱与指标计算（P024–P032）

### 3.1 分箱概念（P025）

#### 分箱定义

1. 将连续变量离散化；
2. 将多状态离散变量合并为更少的组。

#### 分箱用途

- 对变量分层；
- 便于统计分析；
- 降低异常值干扰；
- 增强变量鲁棒性；
- 观察风险随变量变化的趋势。

#### 分箱注意事项

1. 必须覆盖变量所有取值，不能丢失信息；
2. 箱数不宜过多，一般控制在 5–8 箱；
3. 每箱样本占比应具有统计意义，课程建议至少约 5%；
4. 缺失值通常单独成箱。

---

### 3.2 分箱算法分类（P026）

分箱可以从以下维度划分：

#### 按变量类型

- 连续变量；
- 离散变量。

#### 按是否使用目标变量

- **有监督分箱**：利用好坏标签，例如卡方分箱、决策树分箱、Optimal Binning。
- **无监督分箱**：不使用目标变量，例如等距、等频、聚类分箱。

#### 常见方法

- 卡方分箱；
- 最优分箱；
- 决策树分箱；
- 等距分箱；
- 等频分箱；
- K-means 聚类分箱；
- 类别合并；
- LabelEncoder 后再分箱。

离散变量可先根据类别坏账率、样本量和业务含义进行合并。

---

### 3.3 分箱统计量（P027–P028）

课程示例变量：“最近 3 个月新型非银金融机构的查询次数”。

| 分箱 | 好客户数 | 坏客户数 | 总客户数 | 好客户占比 | 坏客户占比 | 总客户占比 | 区间坏账率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| [0.0, 0.5) | 796 | 28 | 824 | 40.20% | 20.59% | 38.94% | 3.40% |
| [0.5, 1.5) | 533 | 36 | 569 | 26.92% | 26.47% | 26.89% | 6.33% |
| [1.5, 2.5) | 301 | 23 | 324 | 15.20% | 16.91% | 15.31% | 7.10% |
| [2.5, 3.5) | 166 | 18 | 184 | 8.38% | 13.24% | 8.70% | 9.78% |
| [3.5, 4.5) | 98 | 11 | 109 | 4.95% | 8.09% | 5.15% | 10.09% |
| [4.5, 16.0) | 86 | 20 | 106 | 4.34% | 14.71% | 5.01% | 18.87% |
| 合计 | 1980 | 136 | 2116 | 100% | 100.01% | 100% | 6.43% |

#### 指标含义

- **好客户数 / 坏客户数**：每个箱内好坏样本数量。
- **好客户占比**：箱内好客户数 ÷ 全部好客户数。
- **坏客户占比**：箱内坏客户数 ÷ 全部坏客户数。
- **总客户占比**：箱内总客户数 ÷ 全部客户数。
- **区间坏账率**：箱内坏客户数 ÷ 箱内总客户数。

观察重点：

- 区间坏账率是否随变量递增或递减；
- 每箱样本量是否足够；
- 风险排序是否具有业务合理性；
- 高风险区间是否具有明显的风险抬升。

---

### 3.4 WOE：公式与含义（P029）

WOE（Weight of Evidence，证据权重）：

\[
WOE_i
=
\ln\left(
\frac{Bad_i / Bad_T}{Good_i / Good_T}
\right)
=
\ln\left(\frac{Bad_i}{Bad_T}\right)
-
\ln\left(\frac{Good_i}{Good_T}\right)
\]

其中：

- \(Bad_i\)：第 \(i\) 箱坏客户数；
- \(Bad_T\)：全部坏客户数；
- \(Good_i\)：第 \(i\) 箱好客户数；
- \(Good_T\)：全部好客户数。

WOE 表示每个分箱中坏客户分布相对于好客户分布的差异。

示例：

\[
WOE_{[0,0.5)}
=
\ln(20.59\%) - \ln(40.20\%)
=
-0.6692
\]

课程示例的 WOE：

| 分箱 | WOE |
|---|---:|
| [0.0, 0.5) | -0.6692 |
| [0.5, 1.5) | -0.0168 |
| [1.5, 2.5) | 0.1066 |
| [2.5, 3.5) | 0.4566 |
| [3.5, 4.5) | 0.4911 |
| [4.5, 16.0) | 1.2196 |

WOE 逐步上升，说明查询次数越多，风险越高。

---

### 3.5 IV：公式与含义（P030）

IV（Information Value，信息价值）常用于评估变量对目标变量的预测能力。

每一箱的 IV：

\[
IV_i
=
\left(
\frac{Bad_i}{Bad_T}
-
\frac{Good_i}{Good_T}
\right)
\times WOE_i
\]

变量总 IV：

\[
IV = \sum_{i=1}^{n} IV_i
\]

课程示例：

| 分箱 | WOE | IV |
|---|---:|---:|
| [0.0, 0.5) | -0.6692 | 0.1313 |
| [0.5, 1.5) | -0.0168 | 0.0001 |
| [1.5, 2.5) | 0.1066 | 0.0018 |
| [2.5, 3.5) | 0.4566 | 0.0222 |
| [3.5, 4.5) | 0.4911 | 0.0154 |
| [4.5, 16.0) | 1.2196 | 0.1264 |
| **总计** |  | **0.2972** |

---

### 3.6 IV 使用标准（P031）

| IV 范围 | 预测能力 |
|---|---|
| IV < 0.02 | 几乎没有预测力 |
| 0.02 ≤ IV < 0.10 | 弱 |
| 0.10 ≤ IV < 0.30 | 中 |
| 0.30 ≤ IV < 0.50 | 强 |
| IV ≥ 0.50 | 需要排查，可能存在过拟合或数据泄漏 |

变量筛选不能只看 IV：

- 单变量预测能力强，不代表组合后效果最好；
- 需要控制变量间相关性；
- 需要关注分箱坏账率的排序性；
- 需要保证业务可解释性；
- 需要检查跨时间稳定性。

---

### 3.7 IV 的 Python 实现逻辑（P032）

截图代码通过交叉表统计好坏样本分布，并计算 WOE 与 IV。等价逻辑如下：

```python
import numpy as np
import pandas as pd

def calculate_iv(x: pd.Series, y: pd.Series) -> tuple[float, pd.DataFrame]:
    table = pd.crosstab(x, y, margins=True)

    # 假设 0 为好客户，1 为坏客户
    table["good_pct"] = table[0] / table.loc["All", 0]
    table["bad_pct"] = table[1] / table.loc["All", 1]

    eps = 1e-8
    table["woe"] = np.log(
        (table["bad_pct"] + eps) / (table["good_pct"] + eps)
    )
    table["iv_part"] = (
        table["bad_pct"] - table["good_pct"]
    ) * table["woe"]

    iv = table.loc[table.index != "All", "iv_part"].sum()
    return float(iv), table
```

实际使用时需要处理：

- 分母为零；
- 空箱；
- 极小样本箱；
- 缺失值；
- 特殊值；
- 训练集与 OOT 的分箱一致性。

## 4. 制定规则阈值（P033–P037）

### 4.1 规则效果的两个期望（P034）

#### 期望一：拒绝比例不宜过高

原因：

- 拒绝率过高会明显影响通过率和业务规模；
- 风控流程中存在多个筛选环节，各环节应互相补充；
- 单条规则只应拦截最有把握的高风险客群。

课程建议：

- 单条规则通常只拒绝少量客户；
- 一般命中率 / 拒绝比例不超过约 5%。

#### 期望二：拒绝客群风险显著更高

希望：

- 拒绝客群中坏客户占比越高越好；
- 拒绝客群中好客户占比越低越好；
- 尽量多抓坏客户，少误杀好客户。

---

### 4.2 五个规则评估项（P035）

#### 1）命中率（hit_rate）

定义：

\[
hit\_rate = \frac{规则命中客户数}{总客户数}
\]

也可理解为该规则对总体客户的拒绝比例。

#### 2）精准率（bad_rate）

定义：

\[
bad\_rate = \frac{规则命中客户中的坏客户数}{规则命中客户数}
\]

课程中将其称为规则精准率。

精准率应与整体坏账率对比。例如：

- 整体坏账率 6%；
- 规则命中客群坏账率 18%；
- 则风险约为整体的 3 倍。

#### 3）召回率（recall_rate）

定义：

\[
recall\_rate = \frac{规则命中的坏客户数}{全部坏客户数}
\]

表示规则抓住了多少坏客户。

#### 4）排序性

关注不同区间的坏账率是否按变量大小呈现单调趋势。排序性好，规则阈值更容易解释和调整。

#### 5）可解释性

规则本身应符合业务逻辑，例如：

- 查询次数越多，风险更高；
- 逾期次数越多，风险更高；
- 信用分越低，风险更高。

---

### 4.3 基于分箱的阈值分析（P036）

课程将最后一箱设为拒绝区间：

```text
最近 3 个月新型非银金融机构查询次数 > 4
```

满足条件拒绝，否则通过。

该规则表现：

- 命中率：5.01%；
- 命中客群坏账率：18.87%；
- Lift：18.87% ÷ 6.43% = 2.93；
- 坏客户召回率：14.71%；
- 好客户误杀率：4.34%；
- 分箱坏账率具有明显排序性；
- 规则具有业务可解释性。

---

### 4.4 极端值检测（P037）

极端值检测的基本思想：

> 高风险客群往往是异常客群，其变量取值会集中在常人分布的两端。

做法：

1. 枚举若干分位点，例如：
   - 0.005；
   - 0.01；
   - 0.02；
   - 0.05；
   - 0.95；
   - 0.98；
   - 0.99；
   - 0.995。
2. 以分位点对应值作为候选阈值；
3. 逐个计算 hit_rate、hit_bad_rate、Lift 等指标；
4. 选择命中率适中、风险提升明显的阈值。

课程示例中，阈值约为 `4.25` 时综合效果最佳：

- hit_rate 约 5.01%；
- hit_bad_rate 约 18.87%；
- Lift 约 2.94。

# 四、交叉表规则生成（P039–P055）

## 1. 交叉表的概念（P042–P043）

交叉表是两个或两个以上变量的交叉判断。

示例变量：

- 当前公积金状态。

两个变量形成的是**二维交叉表**；两个以上变量则是多维交叉表。

本质上：

> 交叉表是变量的“笛卡尔积”。

## 2. 交叉表的特点（P044）

从规则复杂度和变量维度看：

```text
单变量规则 → 二维交叉表 → 多维交叉表 → 逻辑回归评分卡
简单、维度少 ------------------------------> 复杂、维度多
```

特点：

- 比单变量规则维度更多，风险评估更精确；
- 比评分卡模型维度更少、复杂度更低；
- 开发和调优速度更快；
- 兼顾维度和复杂度；
- 属于规则与模型之间的中间形态。

---

## 3. 生成交叉表的前置条件（P045–P046）

### 条件一：先筛选预测能力较好的变量池

从高 IV、业务合理、稳定的变量中选择交叉组合。

一般原则：

- 变量来自不同风险维度；
- 变量之间相关性不宜过高；
- 组合后应带来额外风险区分能力。

### 条件二：连续变量先分箱

- 连续变量需要分箱并保证顺序性；
- 离散变量可直接作为行列；
- 缺失值和特殊值应单独处理。

### 条件三：总样本和坏样本数量足够

交叉后格子数量会快速增加。

例如：

- 单变量有 4 个箱；
- 与 3 个状态的离散变量交叉后变成 12 个格子；
- 如果总样本和坏样本不足，每个格子可能样本过少，导致坏账率波动或无法统计。

因此每个格子都应有足够样本。

# 五、决策树规则生成（P056–P079）

## 1. 决策树的概念（P057–P060）

### 1.1 什么是决策树（P059）

决策树是一组 if-then 规则的集合，自上而下按照某种度量标准不断分裂，形成树形结构。

节点类型：

- **根节点**：树的起始节点；
- **内部节点 / 分裂节点**：根据特征及阈值继续划分；
- **叶子节点 / 末端节点**：不再继续分裂，输出最终类别或数值。

### 1.2 决策树的生成过程（P060）

从根节点开始：

1. 在每个分裂节点，从特征池中选择最优变量；
2. 选择该变量对应的最优阈值；
3. 将样本划分为两个或多个子集；
4. 继续向下递归分裂；
5. 达到停止条件后输出叶子节点结果。

决策树通过变量组合对特征空间进行非线性划分，因此属于一种**非线性模型**。

---

## 2. 决策树算法（P061–P070）

### 2.1 算法分类（P062）

常见决策树算法：

- ID3；
- C4.5；
- CART。

区别：

| 算法 | 任务 | 常用划分指标 | 是否二叉树 |
|---|---|---|---|
| ID3 | 分类 | 信息增益 | 不一定 |
| C4.5 | 分类 | 信息增益率 | 不一定 |
| CART | 分类、回归 | 基尼系数 / 残差平方和 | 是 |

课程重点介绍 CART，因为：

- 可做分类和回归；
- 二叉树计算效率较高；
- 是随机森林、GBDT 等集成树模型的基础。

---

### 2.2 CART 分类树：基尼系数（P063–P065）

对于数据集 \(D\)，基尼指数：

\[
Gini(D)
=
\sum_{k=1}^{K} p_k(1-p_k)
=
1-\sum_{k=1}^{K}p_k^2
\]

二分类情况下：

\[
Gini(p)=2p(1-p)
\]

含义：

- Gini 越小，数据纯度越高；
- Gini 越大，类别越混杂。

示例：

- 好坏客户各占 50%：
  \[
  Gini=2\times0.5\times0.5=0.5
  \]
- 全部为好客户或全部为坏客户：
  \[
  Gini=0
  \]

按特征 \(A\) 划分后：

\[
Gini(D|A)
=
\sum_{i=1}^{n}
\frac{|D_i|}{|D|}
Gini(D_i)
\]

二叉切分：

\[
Gini(D|A)
=
\frac{|D_1|}{|D|}Gini(D_1)
+
\frac{|D_2|}{|D|}Gini(D_2)
\]

选择加权 Gini 最小的变量和切分点。

---

### 2.3 CART 分类树：变量二分法（P066–P067）

#### 连续变量

假设变量有 \(m\) 个不同取值，从小到大排列。

- 可形成 \(m-1\) 个候选切分点；
- 切分点通常取相邻值的中点；
- 每个切分点将数据分为 \(D_1\) 和 \(D_2\)；
- 计算每个切分点的加权 Gini；
- 选择最小者作为最优切分。

#### 离散变量

对具有多个类别的变量进行二分：

- 取一个类别作为一组；
- 其余类别作为另一组；
- 枚举候选类别组合；
- 计算每种划分的加权 Gini；
- 选择 Gini 最小的划分。

---

### 2.4 CART 分类树递归生成（P068）

输入：

- 训练集 \(D\)；
- 基尼系数停止阈值；
- 最小切分样本数。

输出：

- 分类树 \(T\)。

递归步骤：

1. 若当前节点样本数小于阈值，或没有可用特征，则停止；
2. 计算当前节点数据集的 Gini；
3. 若 Gini 小于停止阈值，则停止；
4. 计算所有特征及候选取值对应的 Gini；
5. 选取 Gini 最小的特征 \(A\) 和最优切分点 \(a\)；
6. 按该切分将数据划分为 \(D_1\) 和 \(D_2\)；
7. 生成左右子节点；
8. 对左右节点重复以上步骤。

预测时：

- 样本沿树结构进入某个叶子节点；
- 分类结果取该叶子节点中占比最高的类别。

---

### 2.5 CART 回归树预测方式（P069）

回归树的目标变量是连续值。

预测逻辑：

1. 每个输入样本落入一个叶子区域 \(R_m\)；
2. 该叶子节点预测值为该区域内训练样本目标值的均值；
3. 回归树可表示为：

\[
f(x)
=
\sum_{m=1}^{M}
c_m I(x\in R_m)
\]

其中：

- \(R_m\)：第 \(m\) 个叶子区域；
- \(c_m\)：该区域目标值均值。

---

### 2.6 CART 回归树：残差平方和（P070）

回归树通常使用 RSS（残差平方和）作为划分标准。

目标是找到变量 \(j\) 和切分点 \(s\)，使左右节点残差平方和最小：

\[
\min_{j,s}
\left[
\min_{c_1}
\sum_{x_i \in R_1(j,s)}
(y_i-c_1)^2
+
\min_{c_2}
\sum_{x_i \in R_2(j,s)}
(y_i-c_2)^2
\right]
\]

RSS 越小，说明节点内样本目标值越集中，切分效果越好。

## 3. 决策树生成规则（P071–P073）

### 3.1 从叶子路径生成规则（P072）

课程示例：

- 样本整体坏账率：6%；
- 决策树深度：2；
- 变量包括征信、公积金、房产等。

```

→ 拒绝
```

否则通过。

### 3.2 决策树规则注意事项（P073）

#### 1）规则复杂度

树越深，客群划分越细，但会带来：

- 训练样本过拟合；

- 上线配置困难；
- 监控和问题定位困难；
- 运营维护成本增加。

课程建议：

> 在信贷风控中，一条规则包含的变量数量一般不超过 3 个。

#### 2）规则评估指标

与单变量和交叉表相同，综合考虑：

- 精准率；
- 召回率；
- 命中率；
- Lift；
- 排序性；
- 稳定性。

#### 3）规则可解释性

通过决策树生成的规则也必须满足业务可解释性，不能仅依赖统计结果。

# 六、规则泛化效果评估（P080–P087）

## 1. 概念（P081–P083）

规则开发后存在两类评估：

### 1）规则生成阶段的评估

用于筛选规则，主要关注：

- 命中率；
- 精准率；
- 召回率；
- Lift；
- 排序性；
- 可解释性。

### 2）规则筛选后的泛化评估

用分析样本以外的数据，评估规则对业务的真实影响，主要关注：

- 逾期率；
- 通过率；
- 规则稳定性。

既可以评估单条规则，也可以评估整个规则集。

---

## 2. 分析流程（P084）

规则泛化效果评估流程：

1. 选择合适的泛化样本；
2. 对规则涉及的底层变量进行回溯和加工；
3. 使用宽表变量复现规则或规则集；
4. 将规则应用于泛化样本；
5. 计算泛化样本上的效果；
6. 与分析样本结果进行对比。

重要要求：

- 泛化评估虽然是规则开发后期环节，但样本方案应提前设计；
- 变量回溯应尽量一次性完成；
- 避免规则开发完成后才发现历史数据无法复现。

---

## 3. 逾期率泛化样本（P085）

泛化评估的逻辑：

> 用历史数据推演规则，验证其对未来风险的识别能力。

时间外样本（OOT）要求：

1. 时间窗口位于分析样本之后；
2. 样本量满足统计意义，一般至少覆盖 3 个月；
3. 与分析样本采用相同的贷后表现定义；
4. 客群和整体风险水平与分析样本基本一致；
5. 按月拆分评估，观察稳定性。

课程示例：

```text
分析样本：12 个月
时间外 OOT：3 个月
当前时点：更晚的观测时点
```

---

## 4. 逾期率评估指标（P086）

### 命中率

\[
命中率
=
\frac{规则命中样本数}{样本总数}
\]

### 精准率

\[
精准率
=
\frac{规则命中样本中的坏客户数}{规则命中样本数}
\]

### 召回率

\[
召回率
=
\frac{规则命中的坏客户数}{样本总坏客户数}
\]

### Lift

\[
Lift
=
\frac{规则命中客群坏账率}{样本整体坏账率}
\]

### 逾期率下降幅度

课程定义：

\[
逾期率下降幅度
=
\frac{
样本整体坏账率
-
规则通过样本坏账率
}{
样本整体坏账率
}
\]

评估方法：

- 分析样本和 OOT 分别计算上述指标；
- 比较指标变化；
- 若 OOT 指标在分析样本附近小幅波动，则泛化达标；
- 课程建议一般波动不超过 10%，严格时不超过 5%。

示例：

- 分析样本 Lift = 3；
- OOT Lift = 1：效果衰减严重，可能过拟合；
- OOT Lift 在 2.7–3.3：处于 ±10% 范围，泛化能力较好。

---

## 5. 通过率效果评估（P087）

逾期率评估需要足够长的贷后表现，因此 OOT 时间窗口往往距离当前较远，客群可能发生变化。

通过率评估不需要贷后表现，可以使用距离当前更近的新鲜样本。

方法：

1. 选择近期 3 个月或其他新鲜申请样本；
2. 回溯规则变量；
3. 分别计算规则应用前后的通过率；
4. 评估规则对业务规模的影响。

注意：

- 通过率评估样本也需要提前完成变量回溯；
- 通常与逾期率 OOT 样本分开设计；
- 通过率指标可使用 `1 - 命中率`。

# 七、规则集的三种结构（P088–P097）

## 1. 规则集定义（P090–P091）

规则集是一系列规则的集合，在策略中通常对应一个决策节点。

示例规则集：

- 准入规则集；
- 黑名单规则集；
- 反欺诈规则集；
- 征信规则集；
- 多头规则集。

同一规则集可以包含：

- 不同数据源的规则；
- 人工规则；
- 单变量规则；
- 交叉表规则；
- 决策树规则；
- 模型分数规则。

---

## 2. 三种规则集结构（P092–P093）

规则集主要有三种结构：

1. 串行结构；
2. 并行结构；
3. 串行与并行组合结构。

---

## 3. 串行结构（P094）

串行结构按照固定顺序依次执行规则。

特点：

1. 某条规则一旦命中并产生终止决策，后续规则不再执行；
2. 每条规则承接上一条规则过滤后的剩余流量；
3. 各规则命中率是基于不同剩余客群计算的；
4. 通过客户需要未命中所有规则；
5. 规则顺序通常需要设置优先级。

示例：

```text
规则1 → 规则2 → 规则3 → … → 规则N
             ↓
            拒绝
```

顺序设计示例：

- 先使用内部黑名单；
- 未命中后再调用外部付费黑名单；
- 可以节约外部数据调用成本。

---

## 4. 并行结构（P095）

并行结构中的规则相互独立、全部执行。

特点：

1. 没有前后顺序；
2. 每条规则都输出是否命中；
3. 同一客户可以命中多条规则；
4. 只要命中其中一条即可拒绝；
5. 所有规则均未命中才通过。

---

## 5. 串行与并行的比较（P096）

| 对比项 | 串行规则集 | 并行规则集 |
|---|---|---|
| 执行效率 | 规则很多时效率较高，命中后可提前终止 | 规则很多时全部执行，效率较低 |
| 数据获取 | 部分规则不执行，无法获得全部规则命中表现 | 全部规则执行，可获得完整单一命中和组合命中数据 |
| 监控分析 | 未执行规则缺少命中数据，不利于监控和迭代 | 便于分析单一命中、交叉命中和相互覆盖 |
| 使用场景 | 有明确优先级、成本控制或前置拦截场景 | 规则无优先级，需要贷后监控和调优分析 |

实际策略中常采用串并行组合：

- 外层按规则集串行；
- 规则集内部采用并行；
- 关键强规则允许提前终止；
- 其余规则保留完整命中日志。

P097 为本章节结束页。

## 2. 规则集线下性能测试的三个核心指标（P100）

### 1）综合命中率

表示规则集整体拒绝的客户比例。

### 2）整体坏账率

表示规则集命中客群中的坏客户占比，反映规则集整体风险识别效果。

### 3）相互覆盖率

反映规则之间的重叠情况，以及单条规则的独立贡献。

---

## 3. 综合命中率（P101）

综合命中率是规则集作为整体的最终命中率。

注意：

- 不等于各规则命中率简单相加；
- 原因是客户可能同时命中多条规则；
- 规则集命中条件取决于决策逻辑。

课程示例：

### 至少命中 1 条即拒绝

- 规则 1 命中率：3/8 = 37.5%；
- 规则 2 命中率：4/8 = 50.0%；
- 规则集命中率：5/8 = 62.5%。

### 至少命中 2 条才拒绝

- 规则集命中率：2/8 = 25.0%。

因此，规则集综合命中率取决于：

- OR / AND 逻辑；
- 最少命中条数；
- 规则间重叠程度。

---

## 4. 整体坏账率（P102）

整体坏账率同样针对规则集整体计算。

计算步骤：

1. 根据单条规则命中结果生成规则集命中标记；
2. 满足规则集拒绝条件的客户记为命中；
3. 统计规则集命中客户中的坏客户占比。

课程示例（至少命中 1 条即拒绝）：

| 对象 | 命中率 | 命中客群坏账率 |
|---|---:|---:|
| 规则 1 | 3/8 = 37.5% | 2/3 = 66.7% |
| 规则 2 | 4/8 = 50.0% | 3/4 = 75.0% |
| 规则集 | 5/8 = 62.5% | 4/5 = 80.0% |

规则集整体坏账率不等于单规则坏账率平均值。

---

## 5. 相互覆盖率与单一命中率（P103）

### 相互覆盖率

统计一条规则的命中是否被其他规则覆盖。

若某规则命中客户全部被其他规则覆盖，则：

- 删除该规则后，规则集命中结果不变；
- 该规则缺乏独立贡献；
- 可以考虑删除或降级。

### 单一命中率

表示只命中该规则、未命中其他规则的客户比例。

课程示例：

| 规则 | 命中率 | 单一命中率 |
|---|---:|---:|
| 规则 1 | 3/8 = 37.5% | 0% |
| 规则 2 | 4/8 = 50.0% | 1/8 = 12.5% |
| 规则 3 | 4/8 = 50.0% | 1/8 = 12.5% |

结论：

1. 规则 1 的命中全部被规则 3 覆盖，可以优先删除规则 1；
2. 删除规则 1 后，再重新计算规则 2、规则 3 的单一命中率；
3. 相互覆盖分析需要按顺序迭代，不能一次性静态判断。

# 九、核心公式与指标速查

## 1. 单规则指标

\[
命中率
=
\frac{命中客户数}{总客户数}
\]

\[
精准率
=
\frac{命中客户中的坏客户数}{命中客户数}
\]

\[
召回率
=
\frac{命中的坏客户数}{全部坏客户数}
\]

\[
Lift
=
\frac{命中客群坏账率}{整体坏账率}
\]

---

## 2. WOE 与 IV

\[
WOE_i
=
\ln
\left(
\frac{Bad_i / Bad_T}{Good_i / Good_T}
\right)
\]

\[
IV_i
=
\left(
\frac{Bad_i}{Bad_T}
-
\frac{Good_i}{Good_T}
\right)
\times WOE_i
\]

\[
IV
=
\sum_i IV_i
\]

---

## 3. 基尼指数

\[
Gini(D)
=
1-\sum_{k=1}^{K}p_k^2
\]

二分类：

\[
Gini(p)=2p(1-p)
\]

划分后：

\[
Gini(D|A)
=
\sum_i
\frac{|D_i|}{|D|}
Gini(D_i)
\]

## 最终总结

整套课程形成了一条完整的规则开发路线：

```text
风险识别
→ 变量开发
→ 样本设计
→ 变量初筛
→ 分箱与 WOE/IV
→ 单变量规则
→ 交叉表规则
→ 决策树规则
→ 单规则效果评估
→ OOT 泛化评估
→ 规则集组合
→ 规则集线下性能测试
→ 上线验证与监控
→ 持续调优
```

规则开发的核心不是单纯追求高坏账率，而是在以下目标间取得平衡：

- 风险识别能力；
- 命中率与业务规模；
- 好客户误杀；
- 坏客户召回；
- 稳定性；
- 可解释性；
- 数据成本；
- 规则复杂度；
- 规则之间的独立贡献；
- 上线后的可监控、可维护和可迭代。
