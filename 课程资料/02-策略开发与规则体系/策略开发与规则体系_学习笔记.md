# 一、规则的认识和类型

## 1.1 规则的概念

规则是**基于变量（特征）的一系列判断条件组合**。

核心理解：

1. 规则基于特征变量产生，因此数据和变量是制定规则的先决条件。
2. 规则可以是一个判断条件，也可以是多个判断条件的组合。
3. 规则层位于数据层与决策层之间：
   - 数据层：变量或特征；
   - 规则层：判断条件；
   - 决策层：通过、拒绝或其他处置结果。

示例：

```text
单条件规则：年龄 > 60
组合规则：性别 = 男 AND 年龄 > 60
```

## 1.2 规则的作用

规则的主要作用是**筛选和细分客户**。

在信贷风控中，规则主要用于：

- 识别并筛选不同风险水平的客户；
- 拒绝高风险客户；
- 通过低风险客户；
- 对特定风险点进行直接拦截；
- 降低业务整体风险。

示例：

```text
变量：过去 12 个月的逾期次数
规则：逾期次数 > 3
处置：满足条件则拒绝，否则通过
```

课件示例中，拒绝组逾期率约为 8%，通过组逾期率约为 2%，说明该规则具有一定风险区分能力。

## 1.3 规则与策略的关系

在信贷风控中：

- **模型和规则都是策略的工具**；
- 策略是对数据、规则、模型、流程顺序和处置方式的综合管理；
- 一个完整策略通常需要明确：
  - 使用哪些数据；
  - 使用哪些规则和模型；
  - 阈值如何设置；
  - 规则和模型的调用顺序；
  - 在流程中的使用位置；
  - 命中后采取何种处置。

典型贷前审批流程：

```text
客户申请 → 规则判断 → 模型评分 → 决策结果
                    ↑
                   数据
```

## 1.4 规则的特点

与模型相比，规则具有以下特点：

1. **能够识别明确、特定的风险点**；
2. **可解释性更强**，判断逻辑清晰透明；
3. **灵活性更高**，可以随风险变化快速调整；
4. 更便于配置、监控、上线和运营维护。

模型通常基于大量特征，通过回归、机器学习或复杂算法输出概率或评分。规则则更像对单个变量或少量变量进行条件判断。

可以把模型理解为“由大量复杂规则共同形成的统计判断系统”。

# 二、规则的分类

## 2.1 按数据来源分类

课件将规则按数据维度分为以下类型。

### 1. 征信类规则

基于征信报告中的信息制定，例如：

- 征信查询次数；
- 逾期次数；
- 信贷账户数量；
- 历史还款表现；
- 当前负债及授信情况。

### 2. 多头共债类规则

从征信报告或第三方数据中获取借贷行为信息，用于识别：

- 多平台借款；
- 短期频繁申请；
- 多头负债；
- 现金贷或小贷活跃程度。

### 3. 欺诈类规则

基于反欺诈数据源识别：

- 身份欺诈；
- 设备欺诈；
- 团伙欺诈；
- 信息伪造；
- 异常注册和异常申请行为。

### 4. 运营商类规则

基于手机运营商数据评估：

- 手机号使用时长；
- 通话活跃度；
- 联系人结构；
- 通话异常；
- 号码稳定性；
- 欺诈及逾期风险。

### 5. 司法类规则

基于司法、法院和执行数据识别：

- 失信被执行；
- 法院诉讼；
- 限制高消费；
- 执行案件；
- 其他司法风险。

### 6. 设备类规则

通过 SDK 或设备数据识别：

- APP 列表；
- GPS；
- IP；
- 设备型号；
- 系统版本；
- 使用时长；
- 设备环境；
- 模拟器、改机或异常设备风险。

### 7. 消费类规则

通过银行卡消费和支付数据评估：

- 收入与消费能力；
- 资金稳定性；
- 消费结构；
- 异常交易；
- 财务压力和风险水平。

## 2.2 按策略用途分类

### 1. 准入规则

用于判断客户是否满足基础政策要求，例如：

- 年龄；
- 职业；
- 地域；
- 身份条件；
- 监管和公司政策要求。

### 2. 黑名单规则

包括内部黑名单和外部黑名单，可进一步细分为：

- 逾期类；
- 法院类；
- 限高类；
- 欺诈类；
- 高风险客户名单。

### 3. 反欺诈规则

主要识别：

- 设备异常；
- 通讯录异常；
- 地址及定位异常；
- 埋点行为异常；
- 申请行为异常。

### 4. 身份核验规则

用于校验：

- 姓名、身份证、手机号三要素一致性；
- 手机号状态；
- 联系人状态；
- 身份信息真实性。

### 5. 多头共债规则

用于识别借款人的多头借贷行为，数据主要来自征信和第三方数据。

### 6. 评分规则

根据模型输出的分数设置阈值，例如：

- 低于某分拒绝；
- 中间分进入人工审核；
- 高于某分自动通过。

评分规则可以应用于：

- 风险评分；
- 反欺诈评分；
- 信用评分；
- 消费能力评分。

## 2.3 按强弱程度分类

### 强规则（Hard Check）

强规则也叫硬规则，特点是：

- 规则条件非常严格；
- 命中后通常直接拒绝；
- 一般不做人工调整；
- 阈值不宜频繁变化。

示例：

```text
历史逾期次数 > 10 次 → 直接拒绝
```

强规则多用于风险极高、政策明确或监管禁止的情形。

### 弱规则（Soft Check）

弱规则也叫软规则，特点是：

- 条件设置更灵活；
- 参数容易调整；
- 可结合其他规则共同判断；
- 常用于客户风险分层、人工审核或策略补充。

弱规则通常需要根据线上表现持续调整。常见需要关注的对象是：

- 命中率较低但风险较高的规则；
- 风险变化明显的规则；
- 随业务周期需要动态调整的规则。

## 2.4 设备规则案例

课件展示了一组基于手机厂商设备数据形成的规则表，字段包括：

- 规则类别；
- 基础数据；
- 数据层级；
- 数据含义；
- 规则名称；
- 规则描述；
- 规则强度；
- 处置方式。

代表性设备规则包括：

- 是否为样机或异常设备；
- 设备首次激活时间距今月份；
- 开机天数是否过长；
- 沉默天数是否过长；
- 最近使用频次是否过低；
- 移动运营商是否未知；
- 用户体验改进计划开关状态；
- 设备登录过多账号；
- EMUI 或系统版本是否过低；
- 常用联网方式是否异常；
- 职业判断与申请信息是否不符；
- 当前安装的 APP 类型或数量异常；
- 近 30 天新安装 APP 类型过多；
- 近 30 天 APP 使用次数过少。

这些规则可分别配置为强规则或弱规则，并设置拒绝、审核或其他处置。

# 三、规则分析全流程

## 3.1 完整流程

规则完整流程分为两大模块：

1. **规则离线开发和评估**；
2. **规则上线验证和监控**。

### 人工制定规则流程

```text
风险识别 → 人工规则 → 变量开发 → 样本选取 → 效果评估
```

### 量化制定规则流程

```text
变量开发 → 样本选取 → 量化规则 → 效果评估
```

### 上线后的闭环

```text
规则上线 → 规则验证 → 规则监控 → 规则调整 → 再次上线
```

规则应形成持续迭代的闭环，而不是一次性配置后长期不动。

## 3.2 人工规则与量化规则

人工规则和量化规则的核心区别是：

- **人工规则**：先基于风险认知形成规则目标，再开发变量；
- **量化规则**：先从数据中开发大量变量，再通过统计分析筛选规则。

二者各有优缺点：

- 人工规则有明确业务标准，但风险覆盖不一定全面；
- 量化规则能够更充分地识别数据风险，但部分变量可能缺乏解释性；
- 实际业务中应结合使用，互相补充。

## 3.3 离线开发与评估

### 1. 变量开发

对底层数据进行抽象和关联，衍生多维度高级变量。

### 2. 样本选取

遵循样本选择原则，完成：

- 样本范围定义；
- 好坏标签定义；
- 训练集和测试集划分；
- 必要时增加时间外样本。

### 3. 量化规则生成

常用方法包括：

- WOE / IV；
- 分箱后区间风险排序；
- 业务可解释性判断；
- Lift；
- Cutoff 阈值分析；
- 单变量规则；
- 交叉表规则；
- 决策树规则。

### 4. 效果评估

将规则应用到具有贷后表现的样本中，评估：

- 逾期率；
- 命中率；
- 通过率；
- 坏客户召回率；
- 风险区分能力。

## 3.4 上线验证与监控

### 1. 规则上线

将评估通过的规则配置到策略引擎或生产环境。

### 2. 规则验证

检查：

- 线上配置是否正确；
- A/B 测试或分流结果是否正常；
- 线上命中率与线下结果是否一致；
- 变量计算是否一致。

### 3. 规则监控

按日、周或月持续监控。发现异常时应预警。

### 4. 规则调整

对已上线规则进行复盘，结合线上表现调整阈值、顺序、处置或规则组合。

# 四、单变量规则生成

## 4.1 单变量规则生成的三个步骤

1. 对变量进行描述性统计，完成初步筛选；
2. 对保留变量分箱，计算统计量、WOE 和 IV，进行二次筛选；
3. 基于分箱风险表现和极端值检测制定规则阈值。

## 4.2 变量初筛

### 为什么需要初筛

真实项目中往往有数百到数千个变量，存在以下问题：

- 部分变量不适用于规则；
- 变量效果高度重叠；
- 规则过多会导致策略不稳定；
- 后续开发和维护工作量巨大。

因此，需要根据以下指标初筛：

- 缺失率；
- 众数占比；
- 唯一值数量；
- 平均值；
- 最大值；
- 最小值；
- 标准差；
- 数据类型。

不符合要求的变量应先删除，以减轻后续筛选压力。

课件示例指出：

- 缺失率达到 60%、众数占比达到 90% 的变量，信息量较低；
- 分布较充分、取值有区分度的变量更适合后续分箱分析。

### Python 示例：描述性统计

```python
import pandas as pd


def simple_statistics(df: pd.DataFrame) -> pd.DataFrame:
    stats = []

    for col in df.columns:
        stats.append([
            col,
            df[col].nunique(),
            df[col].isnull().sum() * 100 / df.shape[0],
            (df[col] == -999).sum() * 100 / df.shape[0],
            df[col].value_counts(normalize=True, dropna=False).iloc[0] * 100,
            df[col].dtype,
        ])

    stats_df = pd.DataFrame(
        stats,
        columns=[
            "Feature",
            "Unique_values",
            "Percentage_of_null",
            "Percentage_of_999",
            "Percentage_of_mode",
            "Type",
        ],
    )

    return stats_df.sort_values(
        "Unique_values", ascending=False, inplace=False
    )
```

## 4.3 分箱概念

### 分箱定义

分箱是将连续变量离散化，并把相近取值合并到有限数量区间中的过程。

### 分箱用途

- 对变量进行分层；
- 便于统计分析；
- 降低异常值影响；
- 提升规则稳定性和鲁棒性；
- 支持 WOE、IV、Lift 和阈值分析。

### 分箱注意事项

1. 分箱必须覆盖变量的全部取值；
2. 不应丢失数据；
3. 一般分为 5～8 箱；
4. 每个箱应有足够样本，通常至少占总样本的一定比例；
5. 缺失值应单独成箱；
6. 每个箱应具有业务和统计意义。

课件用考试成绩举例：

- 40、55、58：不及格；
- 66、71、77：及格；
- 83、91、98：优秀。

## 4.4 分箱算法分类

常见分箱方法包括：

### 连续变量

- 等频分箱；
- 等距分箱；
- 最优分箱；
- 卡方分箱（ChiMerge）；
- 决策树分箱；
- 基于 KS 的分箱；
- 聚类分箱。

### 离散变量

- 按类别直接分箱；
- 按风险排序后合并；
- 监督式聚类或树模型分箱；
- 无监督聚类分箱。

分箱方法可分为监督式和无监督式，区别在于是否利用目标标签。

## 4.5 分箱统计量

课件示例变量为“最近 3 个月某类非银金融机构查询次数”，取值范围约为 0～16，共分为 6 箱。

| 分箱 | 好客户数 | 坏客户数 | 总客户数 | 好客户占比 | 坏客户占比 | 总客户占比 | 区间坏账率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| [0, 0.5) | 796 | 28 | 824 | 40.20% | 20.59% | 38.94% | 3.40% |
| [0.5, 1.5) | 533 | 36 | 569 | 26.92% | 26.47% | 26.89% | 6.33% |
| [1.5, 2.5) | 301 | 23 | 324 | 15.20% | 16.91% | 15.31% | 7.10% |
| [2.5, 3.5) | 166 | 18 | 184 | 8.38% | 13.24% | 8.70% | 9.78% |
| [3.5, 4.5) | 98 | 11 | 109 | 4.95% | 8.09% | 5.15% | 10.09% |
| [4.5, 16.0] | 86 | 20 | 106 | 4.34% | 14.71% | 5.01% | 18.87% |
| 合计 | 1980 | 136 | 2116 | 100% | 100% | 100% | 6.43% |

### 统计量含义

#### 数量统计

统计每个箱中的：

- 好客户数量；
- 坏客户数量；
- 总客户数量。

#### 分布占比

```text
某箱好客户占比 = 某箱好客户数 / 全部好客户数
某箱坏客户占比 = 某箱坏客户数 / 全部坏客户数
某箱客户占比   = 某箱总客户数 / 全部客户数
```

#### 区间坏账率

```text
区间坏账率 = 某箱坏客户数 / 某箱总客户数
```

### 统计量的业务意义

- 总客户占比可以近似理解为规则命中率；
- 区间坏账率用于判断风险水平和风险排序；
- 好坏客户占比差异用于衡量一个箱对坏客户的集中程度；
- 如果高风险箱具有较高坏客户占比和较低好客户占比，说明该区间适合形成拒绝规则。

示例：若把最后一箱作为拒绝区间：

- 命中约 5.01% 的客户；
- 覆盖约 14.71% 的坏客户；
- 仅覆盖约 4.34% 的好客户。

## 4.6 WOE 公式和含义

WOE（Weight of Evidence，证据权重）用于衡量某一分箱中好坏客户分布的差异。

$$
WOE_i = \ln\left(\frac{Bad_i / Bad_T}{Good_i / Good_T}\right)
$$

等价于：

$$
WOE_i = \ln\left(\frac{Bad_i}{Bad_T}\right)
- \ln\left(\frac{Good_i}{Good_T}\right)
$$

其中：

- $Bad_i$：第 $i$ 箱坏客户数；
- $Bad_T$：全部坏客户数；
- $Good_i$：第 $i$ 箱好客户数；
- $Good_T$：全部好客户数。

示例 WOE：

| 分箱 | WOE |
|---|---:|
| [0, 0.5) | -0.6692 |
| [0.5, 1.5) | -0.0168 |
| [1.5, 2.5) | 0.1066 |
| [2.5, 3.5) | 0.4566 |
| [3.5, 4.5) | 0.4911 |
| [4.5, 16.0] | 1.2196 |

WOE 越大，说明该箱的坏客户相对集中程度越高。

## 4.7 IV 公式和含义

单个分箱的 IV：

$$
IV_i = \left(\frac{Bad_i}{Bad_T} - \frac{Good_i}{Good_T}\right) \times WOE_i
$$

变量总体 IV：

$$
IV = \sum_{i=1}^{n} IV_i
$$

示例中各箱 IV 约为：

| 分箱 | IV |
|---|---:|
| [0, 0.5) | 0.1313 |
| [0.5, 1.5) | 0.0001 |
| [1.5, 2.5) | 0.0018 |
| [2.5, 3.5) | 0.0222 |
| [3.5, 4.5) | 0.0154 |
| [4.5, 16.0] | 0.1264 |
| 合计 | 0.2972 |

该变量的 IV 约为 0.2972，具有较好的风险区分能力。

## 4.8 IV 使用标准

| IV 范围 | 预测能力 |
|---|---|
| IV < 0.02 | 几乎无预测能力 |
| 0.02 ≤ IV < 0.10 | 弱 |
| 0.10 ≤ IV < 0.30 | 中等 |
| 0.30 ≤ IV < 0.50 | 强 |
| IV ≥ 0.50 | 可能过强，需要排查数据泄漏、穿越或变量异常 |

变量筛选不能只看 IV，还应同时考虑：

- 单变量预测能力；
- 变量之间的相关性；
- 变量因果合理性；
- 业务解释性；
- 时间稳定性。

应优先选择 IV 较高、相关性较低且业务逻辑合理的变量组合。

## 4.9 IV Python 实现

课件给出的核心计算逻辑如下：

```python
import numpy as np
import pandas as pd


def cal_iv(x: pd.Series, y: pd.Series) -> pd.DataFrame:
    """按变量分组计算 WOE 与 IV。"""

    crtab = pd.crosstab(x, y, margins=True)
    crtab.columns = ["good", "bad", "total"]

    crtab["factor_per"] = crtab["total"] / len(y)
    crtab["bad_per"] = crtab["bad"] / crtab.loc["All", "bad"]
    crtab["good_per"] = crtab["good"] / crtab.loc["All", "good"]

    crtab["p"] = crtab["bad_per"]
    crtab["q"] = crtab["good_per"]

    crtab["woe"] = np.log(crtab["p"] / crtab["q"])
    crtab["iv"] = crtab["woe"] * (crtab["p"] - crtab["q"])

    crtab["IV"] = crtab["iv"].sum()
    crtab = crtab.reset_index()
    crtab = crtab.rename(columns={crtab.columns[0]: "var_level"})
    crtab["var_level"] = crtab["var_level"].astype(str)

    return crtab
```

实际项目中还需要处理：

- 0 频数导致的无穷 WOE；
- 缺失值单独成箱；
- 极小箱合并；
- 分箱顺序；
- 数据类型和异常值。

## 4.10 规则效果的两点期望

### 1. 命中率不宜过高

一个策略通常包含多个风险点和多个规则。单条规则只应处理一个相对明确的风险点。

如果单条规则拒绝比例过高，往往会误伤大量好客户，影响业务通过率。课件建议单条拒绝规则的命中率通常不宜超过约 5%，具体仍需结合业务目标。

### 2. 拒绝组风险应明显高于通过组

理想规则应做到：

- 拒绝客户中的坏客户占比较高；
- 通过客户中的坏客户占比较低；
- 尽量拒绝更多坏客户，同时保留更多好客户。

## 4.11 规则效果的五项评估指标

### 1. 命中率（Hit Rate）

```text
命中率 = 被规则拒绝的客户数 / 总客户数
```

命中率过高会显著影响通过率。

### 2. 精准率（Bad Rate / Precision）

```text
精准率 = 被规则拒绝客户中的坏客户数 / 被规则拒绝客户数
```

通常希望显著高于整体坏账率。

### 3. 召回率（Recall Rate）

```text
召回率 = 被规则拒绝的坏客户数 / 全部坏客户数
```

衡量规则覆盖了多少坏客户。

### 4. 排序性

按变量分箱后，区间坏账率应呈现较明确的单调或有序趋势。排序性越好，变量越容易形成稳定阈值。

### 5. 可解释性

变量和阈值应具有清晰的业务含义，能够解释为何该条件代表更高风险，也便于上线、审计和运营。

## 4.12 基于分箱 IV 分析制定阈值

以前述变量为例，最后一箱风险最高：

```text
规则：最近 3 个月某类非银金融机构查询次数 > 4.5
处置：拒绝
```

效果约为：

- 命中率：5.01%；
- 拒绝组坏账率：18.87%；
- 整体坏账率：6.43%；
- Lift：18.87% / 6.43% ≈ 2.93；
- 坏客户召回率：20 / 136 ≈ 14.71%；
- 好客户损失占比：86 / 1980 ≈ 4.34%。

## 4.13 极端值检测制定阈值

高风险客户通常只占少数，其变量值可能集中在极端区间。

极端值检测方法：

1. 设置多个高低分位点，例如：

```text
0.005、0.01、0.02、0.05、0.95、0.98、0.99、0.995
```

2. 枚举每个分位点对应的变量阈值；
3. 计算每个阈值的命中率、坏账率、Lift 和召回率；
4. 选择风险区分明显且业务损失可接受的阈值。

课件示例中，阈值约为 4.25 时：

- 命中率约 5.01%；
- 拒绝组坏账率约 18.87%；
- Lift 约 2.94。

# 五、交叉表规则生成

## 5.1 交叉表的概念

交叉表是从两个或多个方向，对变量进行连续切分和组合分析的方法。

示例：

- 变量一：最近 6 个月新开信贷账户数；
- 变量二：当前公积金状态。

两个变量形成二维交叉表；三个及以上变量形成多维交叉表。

交叉表本质上可以理解为一个结构简单、人工可控的决策树。

示例二维坏账率：

| 最近 6 个月新开信贷账户数 | 公积金状态=-9999 | 公积金状态=1 | 公积金状态=2 |
|---|---:|---:|---:|
| (-0.001, 0.5] | 4.24% | 1.60% | 2.97% |
| (0.5, 1.5] | 12.60% | 6.12% | 13.04% |
| (1.5, 2.5] | 21.74% | 8.82% | 17.95% |
| (2.5, 28.0] | 19.18% | 12.66% | 34.00% |

## 5.2 交叉表的特点

### 与单变量规则相比

- 维度更多；
- 风险识别更细；
- 区分能力和准确性通常更高。

### 与评分卡或复杂模型相比

- 结构更简单；
- 解释性更强；
- 开发和上线速度更快；
- 更便于策略人员维护。

因此，交叉表在复杂度、准确性和迭代速度之间较为均衡。

## 5.3 交叉表的前置条件

### 1. 变量质量较高

应优先选取：

- IV 较高；
- 单变量效果较好；
- 变量之间相关性较低；
- 具有互补风险含义的变量。

### 2. 连续变量需分箱且有序

连续变量必须先分箱，并保证区间具有合理的风险排序。

离散变量如果类别数量较少，可以直接参与交叉。

### 3. 样本量必须充足

交叉变量会显著增加格子数量。

例如：

```text
变量 A 有 4 个箱，变量 B 有 3 个箱
交叉后共有 4 × 3 = 12 个格子
```

每个格子必须有足够的好坏样本，否则坏账率波动较大，结果不稳定。

## 5.4 交叉表规则生成的三个步骤

1. 基于透视表统计好客户数和坏客户数；
2. 计算每个格子的区间坏账率和客户占比；
3. 基于坏账率、客户占比和业务逻辑制定规则。

## 5.5 透视表

原始数据通常至少包含：

- 客户 ID；
- 变量一；
- 变量二；
- 好坏标签。

可通过透视表分别得到：

- 坏客户数表：对目标标签求和；
- 总客户数表：对客户 ID 或目标标签计数。

## 5.6 指标计算

### 格子坏账率

```text
格子坏账率 = 格子内坏客户数 / 格子内总客户数
```

### 格子客户占比

```text
格子客户占比 = 格子内总客户数 / 全部客户数
```

最终形成四张基础表：

1. 坏客户数；
2. 总客户数；
3. 坏账率；
4. 客户占比。

## 5.7 交叉表规则制定

示例规则：

```text
最近 6 个月新开信贷账户数 ∈ (2.5, 28]
AND 当前公积金状态 = 2
→ 拒绝
否则通过
```

该格子的风险和客户占比可用于判断规则是否值得上线。

## 5.8 策略 D 类调优案例

### 背景

# 六、决策树规则生成

## 6.1 决策树的概念

决策树是一组 **if-then** 规则的集合。

它按照某个特征变量和阈值，对样本空间递归切分，最终形成树结构。

节点类型：

- 根节点；
- 内部节点或分裂节点；
- 叶子节点或终端节点。

CART 决策树通常是二叉树，每个分裂节点只产生两个分支。

## 6.2 决策树的生成过程

从根节点开始：

1. 在当前节点选择一个变量；
2. 选择一个最优切分点；
3. 把样本分成两个子集；
4. 对子节点继续重复该过程；
5. 达到停止条件后生成叶子节点。

决策树通过不断寻找最佳切分，使叶子节点中的样本尽可能“纯”。

## 6.3 决策树算法分类

常见算法包括：

- ID3；
- C4.5；
- CART。

其中：

- ID3 和 C4.5 主要用于分类；
- CART 同时支持分类和回归；
- CART 使用二叉树结构；
- sklearn 主要实现 CART 思路。

常见切分标准：

- ID3：信息增益；
- C4.5：信息增益率；
- CART 分类树：基尼系数；
- CART 回归树：残差平方和。

## 6.4 CART 分类树：基尼系数

CART 是 Classification and Regression Trees 的缩写。

基尼系数用于衡量节点的不纯度。基尼系数越小，节点越纯，切分效果越好。

一般形式：

$$
Gini(D)=\sum_{k=1}^{K}p(x_k)(1-p(x_k))
=1-\sum_{k=1}^{K}p(x_k)^2
$$

二分类时：

$$
Gini(p)=2p(1-p)
$$

按集合中类别数量表示：

$$
Gini(D)=1-\sum_{k=1}^{K}\left(\frac{|C_k|}{|D|}\right)^2
$$

变量 $A$ 切分后的条件基尼系数：

$$
Gini(D|A)=\sum_{i=1}^{n}\frac{|D_i|}{|D|}Gini(D_i)
$$

二叉切分时：

$$
Gini(D|A)=\frac{|D_1|}{|D|}Gini(D_1)+\frac{|D_2|}{|D|}Gini(D_2)
$$

### 基尼系数示例

如果节点中好坏客户各占 50%：

$$
Gini(p)=2\times\frac{1}{2}\times\left(1-\frac{1}{2}\right)=0.5
$$

此时不纯度最大。

如果节点中好客户占 100%：

$$
Gini(p)=2\times1\times(1-1)=0
$$

此时节点最纯。

## 6.5 连续变量二分法

对连续变量：

1. 将 $m$ 个取值从小到大排序；
2. 相邻取值之间产生 $m-1$ 个候选切分点；
3. 每个候选点把样本分为 $D_1$ 和 $D_2$；
4. 计算每个切分点的条件基尼系数；
5. 选择基尼系数最小的切分点。

## 6.6 离散变量二分法

对离散变量，可枚举不同类别组合进行二分：

- 某一类别与其他类别；
- 某几个类别与剩余类别；
- 计算每种分法的基尼系数；
- 选择不纯度最小的分法。

## 6.7 CART 分类树递归生成

输入：

- 训练集；
- 基尼系数阈值；
- 最小样本数；
- 其他停止条件。

输出：分类树。

基本过程：

1. 从根节点开始，当前节点包含全部训练集；
2. 若样本属于同一类别或没有可用特征，则生成叶子节点；
3. 若当前节点基尼系数低于阈值，则停止分裂；
4. 计算每个特征和候选切分点的条件基尼系数；
5. 选择基尼系数最小的变量和切分点；
6. 把数据切分为左右子集；
7. 对左右子节点递归执行以上步骤。

分类树叶子节点的预测结果通常是该节点中占比最高的类别。

## 6.8 CART 回归树

### 预测方式

回归树的目标变量是连续值。

每个叶子节点的预测值通常为该节点中目标变量的均值：

$$
f(x)=\sum_{m=1}^{M}c_m I(x\in R_m)
$$

其中：

- $R_m$：第 $m$ 个叶子区域；
- $c_m$：该区域目标值均值。

### 残差平方和

回归树常用残差平方和 RSS 选择最优切分：

$$
\min_{j,s}\left[
\min_{c_1}\sum_{x_i\in R_1(j,s)}(y_i-c_1)^2+
\min_{c_2}\sum_{x_i\in R_2(j,s)}(y_i-c_2)^2
\right]
$$

选择使左右节点残差平方和最小的变量和切分点，再继续递归。

## 6.9 决策树生成规则案例

假设样本整体坏账率为 6%，拥有以下变量：

- 过去 3 个月查询机构数；
- 是否有房；
- 是否有公积金。

树深为 2，最终形成规则：

```text
过去 3 个月查询机构数 > 6
AND 是否有公积金 = 否
→ 拒绝
否则通过
```

树中不同叶子节点的坏账率示例为：

- 3%；
- 5%；
- 8%；
- 12%。

选择风险最高的叶子路径转化为拒绝规则。

## 6.10 决策树规则注意事项

### 1. 控制规则复杂度

树深越大，客户划分越细，但会带来：

- 训练集过拟合；
- 测试集或 OOT 表现下降；
- 规则过于复杂；
- 线上配置、监控和维护困难。

课件建议，信贷风控中的单条规则一般包含的变量数不要超过 3 个。

### 2. 使用统一评估指标

同单变量和交叉表一样，需要评估：

- 命中率；
- 精准率；
- 召回率；
- Lift；
- 稳定性。

### 3. 保证业务可解释性

由决策树提取的规则仍需满足业务解释要求，不能只依赖模型分裂结果。

## 6.11 sklearn.tree 的 API

主要 API：

```python
from sklearn import tree

# CART 分类树
tree.DecisionTreeClassifier

# CART 回归树
tree.DecisionTreeRegressor
```

sklearn 没有直接实现 ID3 和 C4.5，主要使用经过优化的 CART 思路。

### 主要参数

1. `criterion`
   - 特征选择指标；
   - 分类可选 `gini` 或 `entropy`；
   - 默认通常为 `gini`。

2. `splitter`
   - 节点切分方式；
   - `best`：选择最优切分；
   - `random`：随机选择候选切分。

3. `max_depth`
   - 最大树深；
   - 控制模型复杂度和过拟合。

4. `min_samples_split`
   - 节点继续分裂所需的最小样本数。

5. `min_samples_leaf`
   - 叶子节点允许的最小样本数。

6. `max_features`
   - 每次寻找最佳切分时考虑的最大特征数量。

7. `random_state`
   - 随机种子，用于保证结果可复现。

8. `class_weight`
   - 类别权重，用于处理类别不均衡。

9. `min_impurity_decrease`
   - 只有不纯度下降超过该阈值才继续分裂。

10. `ccp_alpha`
    - 代价复杂度剪枝参数，用于控制剪枝。

- 分裂变量及阈值；
- 节点坏账率；
- 样本数；
- 好坏客户数量；
- 拒绝率；
- 召回率。

# 七、规则泛化效果评估

## 7.1 概念

规则开发完成后，还需要评估其泛化能力。

评估分为两个阶段：

### 规则生成后

在开发样本上评估：

- 命中率；
- 精准率；
- 召回率；
- Lift；
- 通过率。

### 规则上线前后

使用分析样本以外的数据，检验规则对未来业务的影响，主要关注：

- 逾期率表现；
- 通过率表现；
- 稳定性；
- 是否需要调整。

## 7.2 分析流程

1. 选择合适的泛化样本；
2. 按开发阶段的变量逻辑加工泛化样本；
3. 在泛化样本上应用规则；
4. 计算规则效果；
5. 与分析样本结果对比。

虽然泛化效果评估处于规则开发的最后环节，但在开发过程中也应反复检验变量和规则的跨时间稳定性，避免最后才发现问题。

## 7.3 逾期率泛化样本

逾期率泛化评估的目的，是用历史时间外样本模拟规则上线后的未来表现。

样本要求：

1. 时间位于分析样本之后；
2. 样本已经满足贷后表现期定义；
3. 一般选择至少 3 个月，并按月拆分评估；
4. 与分析样本间隔不宜过长；
5. 客群结构和风险水平应尽量接近。

示意：

```text
分析样本：约 12 个月
时间外样本（OOT）：后续约 3 个月
当前观察点：更晚的时间点
```

## 7.4 逾期率泛化评估指标

常用指标：

- 命中率；
- 精准率；
- 召回率；
- Lift；
- 逾期率下降幅度。

### 逾期率下降幅度

```text
逾期率下降幅度
=（样本整体坏账率 - 规则通过样本坏账率）/ 样本整体坏账率
```

应对分析样本和多个时间外样本分别计算指标，再比较波动。

课件建议：

- 泛化样本指标与开发样本接近，说明规则稳定；
- 一般波动不宜超过约 10%；
- 更严格场景可控制在约 5%；
- 如果 Lift、精准率或召回率明显下降，需要重新评估规则。

## 7.5 通过率泛化评估

有时最新样本还没有成熟的贷后表现，无法评估逾期率，但仍可以评估规则对通过率的影响。

通过率泛化样本主要用于：

- 检查命中率和拒绝量；
- 判断新规则是否会导致通过率异常下降；
- 检查变量分布是否发生变化；
- 提前发现策略上线风险。

通过率也受时间、渠道、产品和策略变化影响，因此不能只看一个总体数值，还需要分析变量分布和客群结构。

# 八、规则集的三种结构

## 8.1 规则集定义

规则集是一系列规则的集合，在策略中通常作为一个决策节点。

例如：

- 多个人行征信规则组成“征信规则集”；
- 多个设备规则组成“设备规则集”；
- 不同数据源的规则集可以进一步组成更大的策略节点。

常见规则集包括：

- 准入规则集；
- 黑名单规则集；
- 反欺诈规则集；
- 征信规则集；
- 多头共债规则集。

## 8.2 三种结构

规则集主要有三种结构：

1. 串行结构；
2. 并行结构；
3. 串行与并行组合结构。

## 8.3 串行结构

串行结构按照固定顺序依次执行规则。

```text
规则 1 → 规则 2 → 规则 3 → … → 规则 N
```

若某条规则命中拒绝，后续规则不再执行。

特点：

1. 形成漏斗式筛选；
2. 规则命中互相排斥，后续规则只处理前面未拒绝的客户；
3. 所有规则拒绝量之和等于规则集总拒绝量；
4. 通过客户必须经过全部规则且全部未命中；
5. 规则顺序需要按策略优先级配置；
6. 高成本数据可以放在后面，降低整体调用成本。

示例：黑名单规则集中，可先执行公司内部黑名单，再调用外部黑名单。

## 8.4 并行结构

并行结构中，各条规则彼此独立，无固定先后顺序，全部执行并输出命中结果。

特点：

1. 每个规则都执行；
2. 同一个客户可以同时命中多条规则；
3. 通常只要命中任意一条规则就拒绝；
4. 所有规则都未命中才通过；
5. 便于获取单条规则及规则组合的完整命中情况。

## 8.5 串行与并行结构对比

| 对比项 | 串行规则集 | 并行规则集 |
|---|---|---|
| 执行效率 | 规则较多时效率通常更高，前面拒绝后不再执行 | 规则较多时执行成本更高，所有规则都要运行 |
| 数据获取 | 后续规则可能未执行，无法获得完整命中数据，不利于监控和迭代 | 可获得所有规则的命中情况，便于分析单条和组合效果 |
| 使用场景 | 有明确优先级、强调成本和效率 | 无明确优先级、强调监控和调优 |

实际系统经常使用串并行混合结构：先串行执行高优先级或高性价比规则集，再在某些节点内部并行执行多个规则。

# 九、贷前策略规则集线下性能测试

## 9.1 贷前策略规则集分析流程

课件将完整流程划分为五步：

1. **规则挖掘**
   - 单变量规则；
   - 二维交叉规则；
   - 多维决策树规则。

2. **规则评估**
   - 命中率；
   - 召回率；
   - 精准率；
   - 筛选表现较好的规则。

3. **规则集线下性能测试**
   - 将候选规则组成规则集；
   - 在线下样本中测试组合效果。

4. **规则集线上监控**
   - 定期监控规则集整体命中率；
   - 监控单条规则命中；
   - 监控规则组合命中。

5. **规则调优**
   - 根据监控指标优化规则；
   - 调整阈值、顺序和组合。

## 9.2 规则集线下性能指标

规则集组合后，主要关注三个指标：

1. 综合命中率；
2. 整体坏账率；
3. 相互覆盖率。

前两个指标衡量规则集作为整体的最终决策效果，第三个指标用于分析规则之间的重复程度和边际贡献。

## 9.3 综合命中率

综合命中率是规则集整体的最终拒绝比例。

对于并行规则集：

```text
任意一条规则命中 → 规则集命中
```

因此，规则集综合命中率不等于各单条规则命中率的简单相加或平均，因为不同规则之间存在客户重叠。

课件示例：

- 规则 1 命中率：3/8 = 37.5%；
- 规则 2 命中率：4/8 = 50.0%；
- 规则集命中率：5/8 = 62.5%。

如果将拒绝标准改为“至少命中 2 条规则”，规则集命中率会进一步降低，例如示例中约为 2/8 = 25%。

## 9.4 整体坏账率

规则集整体坏账率是规则集命中客户中的坏客户比例。

计算步骤：

1. 统计每条规则命中情况；
2. 只要客户命中任意一条规则，则记为规则集命中；
3. 计算规则集命中客户中的坏客户比例。

示例：

| 规则 | 命中率 | 命中客户坏账率 |
|---|---:|---:|
| 规则 1 | 3/8 = 37.5% | 2/3 = 66.7% |
| 规则 2 | 4/8 = 50.0% | 3/4 = 75.0% |
| 规则集 | 5/8 = 62.5% | 4/5 = 80.0% |

## 9.5 相互覆盖率与单一命中率

相互覆盖率用于衡量规则之间的命中重叠。

如果某条规则命中的客户全部被其他规则覆盖，则该规则可能没有新增贡献。

### 单一命中率

单一命中率是指：

```text
只命中当前规则、未命中其他规则的客户占比
```

若某规则单一命中率为 0，说明它的命中客户被其他规则完全覆盖。

该指标可用于：

- 删除冗余规则；
- 调整串行规则顺序；
- 判断规则的边际覆盖；
- 降低规则调用成本；
- 优化规则集结构。

# 十、核心方法总结

## 10.1 规则开发的完整闭环

```text
风险识别 / 变量开发
        ↓
样本与标签定义
        ↓
变量初筛
        ↓
分箱、WOE、IV
        ↓
单变量 / 交叉表 / 决策树规则生成
        ↓
命中率、坏账率、召回率、Lift、解释性评估
        ↓
时间外样本泛化验证
        ↓
规则集组合与线下性能测试
        ↓
上线验证、监控与调优
```

## 10.2 三类规则生成方法的对比

| 方法 | 优点 | 局限 | 适用场景 |
|---|---|---|---|
| 单变量规则 | 简单、透明、上线快 | 风险区分较粗 | 明确的单一风险点 |
| 交叉表规则 | 解释性好、区分更细 | 维度增加后样本要求高 | 两到三个互补变量组合 |
| 决策树规则 | 自动寻找多变量组合 | 易过拟合、规则可能复杂 | 从大量变量中发现组合风险 |

## 10.3 规则筛选原则

一条值得保留的规则通常应满足：

- 命中率适中；
- 拒绝组坏账率显著高于总体；
- Lift 较高；
- 坏客户召回率有实际贡献；
- 对好客户损失可控；
- 分箱排序合理；
- 跨时间表现稳定；
- 业务解释清晰；
- 与现有规则重复度较低；
- 线上变量可稳定获取和计算。

## 10.4 规则不是一次性产物

规则需要持续监控和迭代，主要原因包括：

- 客群发生变化；
- 市场环境发生变化；
- 数据源和变量口径变化；
- 产品政策变化；
- 欺诈模式变化；
- 规则之间的覆盖关系变化。

因此，成熟的规则体系应具备：

- 版本管理；
- 线上监控；
- 异常预警；
- 定期复盘；
- OOT 验证；
- 阈值调整；
- 冗余规则清理；
- 策略效果归因。
