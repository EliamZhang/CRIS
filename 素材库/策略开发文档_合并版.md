## 一、核心概念与基础认知

### 1.1 什么是风控规则

风控规则是基于特征变量的一系列判断条件，用于在信贷流程中识别和筛选不同风险水平的人群。

规则的本质可以拆成三层：

```text
数据层 -> 规则层 -> 决策层
特征变量 -> 判断条件 -> 通过/拒绝
```

示例：

- 单变量规则：`年龄 > 60` -> 拒绝
- 组合规则：`性别 = 男` 且 `年龄 > 60` -> 拒绝

### 1.2 规则的核心作用

规则的核心作用是风险识别。通过历史数据分析，把客户按风险水平分层，尽可能拦截高风险客群、放行低风险客群。

示例：

| 客群分层 | 阈值 | 逾期率 | 风险等级 |
|---|---:|---:|---|
| 拒绝组 | 过去12个月逾期次数 > 3 | 8% | 高风险 |
| 通过组 | 过去12个月逾期次数 <= 3 | 2% | 低风险 |

### 1.3 规则与策略的关系

规则是策略的执行单元，策略是规则和模型的组合管理方式。

```text
客户申请
  -> 规则判断
     -> 命中则拒绝
     -> 未命中进入模型
  -> 模型评分
  -> 最终决策
```

规则只负责局部识别能力，策略负责全局编排，包括数据选取、顺序、阈值和决策位置。

### 1.4 规则 vs 模型

| 维度 | 规则 | 模型 |
|---|---|---|
| 识别方式 | 明确条件判断 | 多变量综合评分 |
| 可解释性 | 强 | 一般较弱 |
| 灵活性 | 高 | 较低 |
| 输出形式 | 通过/拒绝 | 概率或分数 |
| 开发方式 | 经验 + 数据分析 | 建模算法 |

## 四、单变量规则开发方法

### 4.1 开发三步流程

1. 变量初筛
2. 分箱与指标计算
3. 阈值制定与效果评估

### 4.2 变量初筛标准

| 淘汰原因 | 判断标准 |
|---|---|
| 缺失率过高 | 显著影响稳定性 |
| 众数占比过高 | 几乎无区分度 |
| 无法分箱 | 缺乏排序性或信息量低 |

### 4.3 分箱原则

| 原则 | 说明 |
|---|---|
| 全覆盖 | 覆盖所有取值 |
| 数量适中 | 一般 5~8 箱 |
| 每箱有量 | 每箱样本占比最好 >= 5% |
| 缺失单独成箱 | 缺失本身可能有风险信息 |

### 4.4 常用分箱算法

| 变量类型 | 常用算法 |
|---|---|
| 连续型变量 | 卡方分箱、最优分箱、决策树分箱、等频、等距 |
| 离散型变量 | 类别合并归类 |

### 4.5 分箱核心统计指标

| 指标 | 含义 |
|---|---|
| 好客户数/坏客户数/总客户数 | 基础统计 |
| 边际好客户占比 | 评估误拒程度 |
| 边际坏客户占比 | 评估拦截能力 |
| 区间占比 | 可近似理解为命中率 |
| 区间坏账率 | 可近似理解为精准率 |

### 4.6 WOE 与 IV

WOE 公式：

$$
WOE_i=\ln\left(\frac{Bad_i/Bad_T}{Good_i/Good_T}\right)
$$

IV 公式：

$$
IV_i=\left(\frac{Bad_i}{Bad_T}-\frac{Good_i}{Good_T}\right)\times WOE_i
$$

$$
IV=\sum_{i=1}^{n}IV_i
$$

WOE 的核心含义：

- WOE 越大，区间越偏向坏客户
- WOE 为正，偏坏客户方向
- WOE 为负，偏好客户方向

IV 的常用解释区间：

| IV区间 | 解释 |
|---|---|
| <= 0.02 | 很弱 |
| (0.02, 0.1] | 偏弱 |
| (0.1, 0.3] | 中等 |
| (0.3, 0.5] | 较强 |
| > 0.5 | 很强，需排查数据穿越 |

### 4.7 WOE/IV 使用注意事项

- 分箱数量不宜过多，通常不要超过 8 箱
- 某箱若全为好或全为坏，要做平滑处理避免分母为 0
- 缺失值建议单独成箱
- 如果相邻箱 WOE 接近或相同，可考虑合并

## 五、规则阈值制定与效果评估

### 5.1 单条规则的两大目标

- 命中率不宜过高，避免明显伤害通过率
- 精准率尽可能高，尽量把坏客户集中拦下

### 5.2 常用评估指标

| 指标 | 定义 |
|---|---|
| 命中率 Hit Rate | 规则命中客户数 / 总客户数 |
| 精准率 Precision | 规则命中客户中的坏客户占比 |
| 召回率 Recall | 命中的坏客户数 / 总坏客户数 |
| Lift | 规则精准率 / 整体坏账率 |
| 好客户误拒率 | 命中的好客户数 / 总好客户数 |

### 5.3 Lift 的理解

$$
Lift=\frac{规则精准率}{整体坏账率}
$$

示例：整体坏账率 6%，规则精准率 18%，则 `Lift = 3`，说明规则识别强度约为整体基线的 3 倍。

### 5.4 阈值制定方法一：基于分箱分析

步骤：

1. 对变量分箱
2. 计算各箱命中率、坏账率、召回率等
3. 选择坏账率高、命中率适中的区间作为阈值
4. 输出规则评估结果

### 5.5 阈值制定方法二：极端值检测

适用于风险集中在极端分位点的变量：

- 变量值极大时风险高
- 或变量值极小时风险高

可在多个极端分位点上试阈值，再按 Hit Rate、Precision、Recall、Lift 综合选优。

## 六、交叉表规则开发方法

### 6.1 交叉表定位

交叉表规则位于单变量规则和模型之间，兼顾可解释性和多维识别能力。

### 6.2 交叉表规则的特点

- 结合两个及以上变量
- 比单变量信息更丰富
- 比模型更容易解释和快速迭代

### 6.3 交叉表规则的前置条件

- 变量本身具备较好区分度
- 最好来自不同维度，且相关性较低
- 交叉后每个格子仍要有足够样本量

### 6.4 交叉表规则生成三步法

1. 制作透视表
2. 计算每个格子的坏账率和客户占比
3. 选择高坏账率且命中率可接受的格子制定规则

### 6.5 交叉表应用场景

适合做精细化调优，特别是：

- 希望较低命中率下获得较高坏账率
- 需要兼顾通过率和风险拦截

## 七、决策树规则开发方法

### 7.1 决策树核心概念

决策树可以看成一组规则的集合，通过不断分裂变量生成树状结构，最终落到叶子节点输出风险结论。

### 7.2 常见算法

| 算法 | 场景 | 特点 |
|---|---|---|
| ID3 | 分类 | 较早期算法 |
| C4.5 | 分类 | 可处理连续变量 |
| CART | 分类/回归 | 二叉树，工程上最常用 |

### 7.3 CART 分类树

常用基尼指数衡量纯度：

$$
Gini = 2p(1-p)
$$

基尼越小，节点越纯。

### 7.4 决策树规则生成注意事项

- 单条树规则涉及变量不宜过多，通常建议不超过 3 个
- 树深度过大容易过拟合
- 离线效果好不等于 OOT 效果好
- 必须保证业务可解释性和可维护性

## 九、规则集认识与结构

### 9.1 什么是规则集

规则集是一组规则的集合，在策略中通常对应一个决策节点。

示例：

- 人行征信规则集
- 黑名单规则集
- 多头规则集

### 9.2 规则集的三种结构

1. 串行规则集
2. 并行规则集
3. 串行并行组合规则集

### 9.3 串行结构

```text
规则1 -> 规则2 -> 规则3 -> ... -> 规则N
```

特点：

- 前一条命中后，后续规则不再执行
- 形成天然的拒绝漏斗
- 适合有优先级顺序的场景
- 可能节省调用成本

### 9.4 并行结构

特点：

- 所有规则都执行
- 同一客户可能同时命中多条规则
- 只要命中任意一条即可拒绝
- 适合后续监控和组合分析

### 9.5 串行 vs 并行

| 维度 | 串行规则集 | 并行规则集 |
|---|---|---|
| 执行效率 | 通常更高 | 通常更低 |
| 数据获取 | 后续未执行规则无表现数据 | 所有规则都有表现数据 |
| 监控调优 | 相对困难 | 更方便 |
| 使用场景 | 有优先级排序 | 无优先级、强调分析监控 |

## 十、规则集线下性能测试

### 10.1 线下测试流程

```text
规则挖掘
-> 单条规则评估
-> 规则组成规则集
-> 规则集离线测试
-> 线上监控
-> 调优
```

### 10.2 三类核心指标

- 综合命中率
- 整体坏账率
- 相互覆盖率与单一命中率

### 10.3 综合命中率

规则集整体命中率不等于内部单条规则命中率简单相加，因为不同规则之间通常存在交叉命中。

若规则集定义为“命中至少 1 条即拒绝”：

$$
综合命中率=\frac{规则集命中样本数}{样本总数}
$$

若规则集定义为“命中至少 2 条即拒绝”，则整体命中率会下降，但通常精准率会上升。

### 10.4 整体坏账率

规则集整体坏账率是规则集命中客户中的坏客户占比：

$$
整体坏账率=\frac{规则集命中客户中的坏客户数}{规则集命中客户数}
$$

它反映规则集整体作为一个决策单元的识别强度。

### 10.5 相互覆盖率与单一命中率

如果一条规则的命中完全被其他规则覆盖，这条规则在规则集中的独立价值很低。

单一命中率指一条规则独立命中的比例。它用于判断：

- 哪些规则有独立贡献
- 哪些规则只是重复覆盖
- 哪些规则应被剔除或降权

实践原则：

1. 先识别被完全覆盖的无效规则
2. 剔除后再重新计算单一命中率
3. 保留有独立贡献的规则

## 十一、规则泛化效果评估

### 11.1 为什么要做泛化评估

规则在分析样本上效果好，不代表上线后仍然有效。上线前需要评估规则在时间外样本（OOT）上的稳定性和泛化能力。

### 11.2 泛化评估与规则筛选评估的区别

- 规则筛选评估：用于从候选规则中选出好规则
- 泛化效果评估：用于检验这些规则在未来样本上的可迁移性

两者关注点不同，但使用的指标有重叠。

### 11.3 泛化评估通用流程

1. 选择合适的泛化样本
2. 对泛化样本做变量回溯
3. 在泛化样本上复现规则或规则集
4. 计算命中率、精准率、召回率、Lift 等
5. 与分析样本效果对比

说明：泛化评估虽然出现在离线开发流程后段，但泛化样本设计和变量回溯方案必须在前期就提前规划。

### 11.4 逾期率效果评估

逾期率泛化评估的核心逻辑是“用历史推演未来”。因此应选取分析样本之后、且已具备充分贷后表现的 OOT 样本。

常用指标：

- 命中率
- 精准率
- 召回率
- Lift
- 逾期率下降幅度

常用公式：

$$
命中率=\frac{规则命中样本数}{样本总数}
$$

$$
精准率=\frac{规则命中坏客户数}{规则命中样本数}
$$

$$
召回率=\frac{规则命中坏客户数}{总坏客户数}
$$

$$
Lift=\frac{规则精准率}{整体坏账率}
$$

判断思路：

- 若 OOT 样本的关键指标只是在分析样本附近小幅波动，通常说明泛化达标
- 若 Lift、精准率、召回率明显衰减，则说明泛化不足

实践中常会参考一个波动容忍区间，例如关键指标在分析样本基础上上下浮动不超过约 10%。

### 11.5 通过率效果评估

通过率评估主要关注规则上线后对业务规模的影响。

关键点：

- 通过率评估不一定需要等到完整贷后表现
- 可使用距离当前更近的新鲜样本
- 但这些样本同样需要变量回溯

关注指标：

- 命中率变化
- 通过率变化
- 分客群通过差异

### 11.6 泛化评估的常见误区

- 只看分析样本，不看 OOT 样本
- 只看精准率，不看通过率影响
- 泛化样本设计过晚，导致无法回溯变量
- 只看单规则，不看规则集整体效果

## 十二、上线监控、调优与经验总结

### 12.1 上线后四步闭环

```text
规则上线 -> 规则验证 -> 规则监控 -> 规则调整
```

### 12.2 上线验证重点

- 决策引擎配置是否正确
- 线上线下命中率是否一致
- AB 测试分流是否正常

### 12.3 监控要点

| 监控项 | 周期 | 说明 |
|---|---|---|
| 命中率稳定性 | 日/周/月 | 识别漂移或配置异常 |
| 规则命中偏差 | 上线初期重点看 | 核对线上线下差异 |
| 坏账率趋势 | 贷后周期 | 判断是否需要调阈值 |

### 12.4 核心经验

1. 规则开发前要先完成样本设计和变量准备。
2. 单条规则命中率通常不宜过高，否则容易伤害通过率。
3. IV 高不代表一定可用，还要看相关性、稳定性和业务含义。
4. 决策树生成的规则不能只追求离线效果，还要控制复杂度。
5. 规则集管理要关注覆盖关系和独立贡献，不要机械堆规则数量。
6. 泛化评估和变量回溯方案必须提前准备。

### 12.5 常见误区

| 误区 | 正确做法 |
|---|---|
| 规则越多越好 | 关注有效覆盖和独立贡献 |
| IV 高的变量全部保留 | 还要看相关性和可解释性 |
| 精准率越高越好 | 必须同时看召回率和命中率 |
| 一条规则解决所有问题 | 规则要在策略中分层协同 |
| 只看离线效果 | 必须做 OOT 泛化评估和上线监控 |

## 附录：快速参考表

### A. 核心公式

| 公式 | 用途 |
|---|---|
| `WOE = ln(边际坏占比 / 边际好占比)` | 衡量分箱区分能力 |
| `IV = Σ[(边际坏占比 - 边际好占比) × WOE]` | 评估变量预测能力 |
| `Lift = 规则精准率 / 整体坏账率` | 衡量规则识别倍数 |
| `Gini = 2p(1-p)` | CART 分类树纯度指标 |

### B. 三种规则开发方法对比

| 方法 | 变量数 | 复杂度 | 典型场景 |
|---|---:|---:|---|
| 单变量规则 | 1 | 低 | 快速筛选、硬规则 |
| 交叉表规则 | 2 | 中 | 精细化调优 |
| 决策树规则 | 2+ | 高 | 挖掘复杂非线性关系 |

### C. 规则集评估重点

| 层级 | 核心指标 |
|---|---|
| 单条规则 | Hit Rate、Precision、Recall、Lift |
| 规则集整体 | 综合命中率、整体坏账率 |
| 规则集内部 | 相互覆盖率、单一命中率 |
| 泛化效果 | OOT 命中率、精准率、召回率、Lift、通过率变化 |
