# rulelift

`rulelift` 是一组彼此独立的风控规则分析子项目，面向规则开发、规则评估、策略调优和策略替换分析。  
仓库当前包含 `10` 到 `17` 共 8 个子项目。每个子项目都可以单独运行，统一入口都是 `python run.py`，核心结果重点查看各自 `output/summary_report.xlsx`。

这份根目录 README 主要给业务同事看，帮助快速理解：

- 每个项目是干什么的
- 适合解决什么业务问题
- 最终会产出什么样的结果
- 背后的方法论大致是什么

如果需要看输入字段、命令参数、sheet 说明和技术细节，请再进入对应子项目查看它自己的 `README.md`。

## 使用原则

- 每个子项目独立运行，不依赖其他子项目
- 统一运行方式为 `python run.py`
- 业务逻辑集中在各子项目 `src/*.py`
- 表格结果统一汇总到各子项目自己的 `output/summary_report.xlsx`

## 项目地图

| 子项目 | 主要作用 | 更适合回答的问题 |
|---|---|---|
| `10_univariate_rule_generation` | 生成单变量候选规则 | 哪个变量单独看就有区分度 |
| `11_rule_crosstab_analysis` | 做双变量交叉分析和自动交叉搜索 | 哪两个变量组合后更容易圈出高风险人群 |
| `12_decision_tree_rule_mining` | 用决策树自动挖掘组合规则 | 多变量组合后能形成哪些可解释规则 |
| `13_lending_club_tree_rule_mining` | Lending Club 场景下的树规则挖掘 | 用更贴近业务可读性的方式查看树规则 |
| `14_ruleset_performance_evaluation` | 评估一整套规则集效果 | 现有规则集整体表现如何，互相是否重叠 |
| `15_rule_d_class_tuning` | 调优 D 类规则本身 | 哪条 D 类规则太松或太严，怎么改更合适 |
| `16_strategy_d_class_tuning` | 在现有策略上新增规则并评估增益 | 新加一条规则值不值得 |
| `17_strategy_replacement_tuning` | 比较新旧策略替换效果 | 新策略能不能替代旧策略，风险和通过率会怎样变化 |

## 每个项目能做什么

### 10. 单变量规则生成

**项目路径**  
`10_univariate_rule_generation`

**它能做什么**

- 自动从输入特征里生成单变量候选规则
- 输出每个变量的分箱、IV 和阈值规则效果
- 帮助从很多字段里快速找到“值得进入下一轮分析”的变量

**适合的业务场景**

- 你刚拿到一份样本宽表，想先做变量初筛
- 你想知道哪些变量单独看就有明显风险区分能力
- 你需要一批可解释的单变量规则候选

**你会看到的效果**

- 哪些变量 IV 更高
- 哪些阈值规则的 lift 更高
- 哪些规则命中率、坏账率、坏样本捕获更平衡

**背后的方法论**

- 先做变量基础统计
- 再做分箱和 IV/WOE 分析
- 然后自动生成 `<=`、`>=` 之类的阈值规则
- 最后按 `hit_rate`、`bad_rate`、`lift`、`bad_capture` 等指标筛规则

一句话理解：  
这是一个“从单个变量里找好规则”的工具。

### 11. 规则交叉分析

**项目路径**  
`11_rule_crosstab_analysis`

**它能做什么**

- 保留手工指定规则的评估能力
- 自动搜索更优的双变量交叉规则
- 输出固定交叉表、自动搜索候选规则和推荐规则

**适合的业务场景**

- 你已经有几条规则，想验证它们效果
- 你怀疑“单变量不够”，想看两个变量组合后是否更有区分度
- 你想挖出 `A + B` 这类更像业务策略的组合规则

**你会看到的效果**

- 哪些字段对最值得交叉分析
- 哪些双变量组合能圈出更高风险样本
- 哪些组合命中率太高，只是在描述“大多数人”

**背后的方法论**

- 对连续变量先分箱
- 对数值型和低基数类别型变量做两两组合
- 计算每个交叉格子的 `hit_rate`、`bad_rate`、`lift`、`bad_capture`
- 用阈值过滤掉覆盖过大、区分度过低的组合
- 最后输出 Top N 推荐规则

一句话理解：  
这是一个“从两个变量的交叉关系里找规则”的工具。

### 12. 决策树规则挖掘

**项目路径**  
`12_decision_tree_rule_mining`

**它能做什么**

- 自动训练决策树模型
- 把树的叶子路径还原成可解释规则
- 同时用 grid search 搜索更优的树参数组合

**适合的业务场景**

- 你不满足于单变量和手工交叉，想让模型自动找组合规则
- 你想知道多个变量一起切分后，最有效的规则路径是什么
- 你想用一种比纯人工枚举更系统的方式发现规则

**你会看到的效果**

- 决策树整体模型指标
- 每条叶子规则的命中率、坏账率、lift
- 不同树参数下的规则质量对比

**背后的方法论**

- 先对类别变量做编码
- 再训练浅层决策树
- 从树的叶节点回溯得到一组 if-else 规则
- 对规则进行样本量、坏账率、lift 等评估
- 用 grid search 比较不同 `max_depth`、`min_samples_leaf` 等参数

一句话理解：  
这是一个“让树模型自动帮你找多变量规则”的工具。

### 13. Lending Club 树规则挖掘

**项目路径**  
`13_lending_club_tree_rule_mining`

**它能做什么**

- 也是做决策树规则挖掘
- 但更偏向 Lending Club 示例场景下的规则可读性展示
- 适合用来做树规则的业务解释和展示

**适合的业务场景**

- 你希望用更直观的方式理解 Lending Club 数据上的树规则
- 你想看规则文本是否更贴近业务表达
- 你需要一个更偏展示型的树规则分析脚本

**你会看到的效果**

- 决策树结构图
- 编码映射
- 可读性更强的规则文本
- 模型与规则的基础指标

**背后的方法论**

- 与 `12` 一样，核心仍然是决策树切分
- 差异主要在输出组织和规则可读性表达上

一句话理解：  
这是一个“更偏业务展示版”的树规则挖掘工具。

### 14. 规则集效果评估

**项目路径**  
`14_ruleset_performance_evaluation`

**它能做什么**

- 评估一整套规则集，而不是单条规则
- 看规则之间是否重叠、是否互相覆盖
- 看整套规则集的命中率、坏账率、lift 和覆盖结构

**适合的业务场景**

- 你已经有一组现成规则，想做整体复盘
- 你想知道某些规则是不是重复了
- 你想知道删掉某条规则后，整体效果会不会明显变化

**你会看到的效果**

- 每条规则的命中情况
- 规则互相覆盖和纯命中分析
- 命中 0 条、1 条、2 条以上规则的人群分布
- 整套规则集的总体效果总结

**背后的方法论**

- 先把每条规则转成命中标记
- 再分析规则之间的重叠、覆盖和纯命中
- 最后站在“规则组合”的视角评估整体效果

一句话理解：  
这是一个“看整套规则集好不好”的工具。

### 15. D 类规则调优

**项目路径**  
`15_rule_d_class_tuning`

**它能做什么**

- 专门针对 D 类规则做调优
- 观察每条规则变量的分箱表现
- 评估调优前后规则命中、通过率和坏账率的变化
- 现在也支持阈值 grid search

**适合的业务场景**

- 你已经有 D 类规则，但不确定阈值是不是合适
- 你想知道哪条规则偏松、哪条偏严
- 你想基于已有 D 类规则集做精调，而不是完全重做

**你会看到的效果**

- 每条规则相关变量的风险分层表现
- 单规则纯命中贡献
- 调优前后命中率、通过率、坏账率的变化
- 自动搜索得到的更优阈值候选

**背后的方法论**

- 先分析规则变量本身的分箱风险表现
- 再基于规则集计算命中分布和纯命中
- 最后做阈值层面的搜索和效果对比

一句话理解：  
这是一个“调规则本身”的工具。

### 16. 新增策略规则调优

**项目路径**  
`16_strategy_d_class_tuning`

**它能做什么**

- 评估在现有策略基础上新增规则有没有价值
- 对单变量新增规则、双变量新增规则都能分析
- 支持 grid search 自动搜索候选新增规则

**适合的业务场景**

- 你不是要重做整套策略，而是想往现有策略上加一条规则
- 你想比较“加规则带来的坏账改善”和“通过率损失”是否值得
- 你想验证某个新变量接进策略后有没有增益

**你会看到的效果**

- 现有规则表现
- 默认新增规则表现
- 自动搜索得到的新增规则候选
- 单变量新增和双变量新增的效果比较

**背后的方法论**

- 保留原有策略作为基线
- 再引入新增变量或新增规则方案
- 比较加规则前后的人群筛选和风险变化
- 用 grid search 搜索更有潜力的新规则

一句话理解：  
这是一个“调策略新增项”的工具。

### 17. 新旧策略替换分析

**项目路径**  
`17_strategy_replacement_tuning`

**它能做什么**

- 比较旧策略和新策略的替换效果
- 评估替换后通过率和风险怎么变
- 支持对 cutoff 和旧等级组合做 grid search

**适合的业务场景**

- 你想用新评分替换旧评分卡
- 你想知道“新策略多放过的人风险如何”
- 你想评估替换方案，而不是只看某一条规则

**你会看到的效果**

- 新旧策略的决策矩阵
- 新策略和旧策略各自的人群分层表现
- 替换后的风险估算结果
- 不同 cutoff / 等级组合下的推荐方案

**背后的方法论**

- 先定义旧策略拒绝逻辑和新策略拒绝逻辑
- 再把样本按新旧策略交叉分组
- 对无法直接观测表现的人群，用分箱风险做估算
- 最后比较不同替换方案下的通过率和坏账率

一句话理解：  
这是一个“评估新策略能不能替旧策略”的工具。

## 这些项目之间的关系

如果从业务使用链路看，可以大致理解为：

1. `10`
   先找单变量候选规则
2. `11`
   看双变量交叉规则有没有更好组合
3. `12` / `13`
   用决策树自动发现更复杂的多变量规则
4. `14`
   对已有规则集做整体效果评估
5. `15`
   调已有 D 类规则本身
6. `16`
   评估往现有策略里新增规则是否值得
7. `17`
   评估新旧策略替换是否值得

它们不是必须串起来跑，但可以组成一个比较完整的规则开发和策略优化分析链路。

## 典型运行方式

```bash
cd 11_rule_crosstab_analysis
pip install -r requirements.txt
python run.py
```

如需指定输入输出：

```bash
python run.py --input input/your_file.csv --output output
```

## 如何选择项目

- 如果你想先从变量里找规则，优先看 `10`
- 如果你想找双变量组合规则，优先看 `11`
- 如果你想让模型自动挖规则，优先看 `12` 或 `13`
- 如果你想评估整套规则集，优先看 `14`
- 如果你想调已有 D 类规则，优先看 `15`
- 如果你想往现有策略里新增规则，优先看 `16`
- 如果你想比较新旧策略替换方案，优先看 `17`
