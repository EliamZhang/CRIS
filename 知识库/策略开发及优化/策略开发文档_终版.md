## 一、核心概念与基础认知

### 1.1 什么是风控规则

风控规则是基于特征变量的一系列判断条件，用于在授信、审批、贷后等流程中识别和筛选不同风险水平的人群。

规则的本质可以拆解为三个层次：

```text
数据层 -> 规则层 -> 决策层
特征变量 -> 判断条件 -> 通过/拒绝
```

示例：

- 单变量规则：`年龄 > 60` -> 拒绝
- 组合规则：`性别 = 男` 且 `年龄 > 60` -> 拒绝

### 1.2 规则的核心作用

规则的核心作用是风险识别。通过历史数据分析，将客户按风险水平分层，拦截高风险客群，放行低风险客群。

示例：

| 客群分层 | 逾期次数阈值 | 逾期率 | 风险等级 |
|---|---:|---:|---|
| 拒绝组 | 过去12个月逾期次数 > 3 | 8% | 高风险 |
| 通过组 | 过去12个月逾期次数 <= 3 | 2% | 低风险 |

经验型判断往往来自业务认知，但必须通过历史数据验证，不能直接以经验替代量化分析。

### 1.3 规则与策略的关系

规则是策略的执行单元，策略是规则与模型的组合管理方式。

典型贷前审批流程如下：

```text
客户申请
  -> 规则判断
     -> 命中则拒绝
     -> 未命中则进入模型
  -> 模型评分
  -> 最终决策
```

规则负责局部识别能力，策略负责全局编排，包括：

- 变量选择
- 阈值定位
- 规则调用顺序
- 决策位置
- 线上监控与调优机制

### 1.4 规则与模型的差异

| 对比维度 | 规则 | 模型 |
|---|---|---|
| 识别能力 | 针对明确模式识别特定风险 | 基于多变量综合评分 |
| 可解释性 | 强 | 一般较弱 |
| 灵活性 | 高，可快速调整 | 较低，需重新开发或重训 |
| 输出形式 | 二元决策，通常为通过/拒绝 | 概率值或分数 |
| 开发方式 | 经验 + 数据分析 | 统计学习/机器学习 |

## 二、规则分类体系

### 2.1 按数据维度分类

| 规则类型 | 数据来源 | 典型内容 | 示例 |
|---|---|---|---|
| 征信类 | 征信报告/银行接口 | 查询次数、逾期记录 | 近3个月查询机构数 > 6 |
| 多头类 | 征信 + 三方数据 | 多头借贷行为识别 | 多平台借贷、申请频次异常 |
| 欺诈类 | 三方数据源 | 欺诈标记、黑名单 | 欺诈名单、团伙标记 |
| 运营商类 | 通讯/运营商数据 | 活跃、社交风险特征 | 通讯录风险、通话行为 |
| 司法类 | 司法数据 | 执行、诉讼、限高 | 被执行、涉诉信息 |
| 设备类 | SDK/设备数据 | 设备、APP、GPS、IP | 沉默设备、异常安装行为 |
| 消费类 | 银行卡/支付数据 | 消费能力与交易行为 | 交易失败、余额不足 |

### 2.2 按策略用途分类

| 规则类型 | 核心用途 | 典型内容 |
|---|---|---|
| 准入规则 | 基础合规筛选 | 年龄、职业、地区等 |
| 黑名单规则 | 极高风险拦截 | 内部黑名单、外部黑名单 |
| 反欺诈规则 | 识别欺诈行为 | 中介欺诈、团伙欺诈、伪冒申请 |
| 身份校验规则 | 验证身份真实性 | 三要素一致、在网状态 |
| 多头共债规则 | 识别多头借贷 | 查询次数、机构数、负债压力 |
| 评分规则 | 模型化风险判断 | 综合评分、欺诈分、信用分 |

### 2.3 按强弱程度分类

| 维度 | 强规则（硬规则） | 弱规则 |
|---|---|---|
| 条件设置 | 极严格 | 相对柔和 |
| 数据类型 | 多为离散型、高风险标签 | 多为连续型、排序型数值 |
| 用途 | 拦截极端高风险客户 | 日常调优和补充识别 |
| 调整频率 | 低 | 高 |
| 典型类别 | 黑名单、反欺诈、身份异常 | 多头、消费、设备行为 |
| 风险含义 | 一旦触发，风险极高 | 风险较高，但需结合其他维度 |

设备类示例：

| 规则描述 | 强度判定 | 理由 |
|---|---|---|
| 设备沉默天数 >= 180天 | 强规则 | 长期不活跃设备明显异常 |
| 当前安装APP类别数 < 3 | 强规则 | 正常用户极少出现 |
| 设备开机天数 >= 360天 | 弱规则 | 有异常倾向，但非绝对异常 |

## 三、规则完整生命周期

### 3.1 生命周期总览

```text
变量开发
-> 样本设计
-> 规则生成
-> 离线评估
-> 上线验证
-> 线上监控
-> 调优迭代
```

### 3.2 两条开发路线

| 维度 | 人工制定规则 | 量化制定规则 |
|---|---|---|
| 起点 | 已知风险点 | 海量变量池 |
| 规则来源 | 业务经验 | 数据驱动 |
| 风险覆盖 | 明确但可能局部 | 更全面，可能发现未知风险 |
| 阈值设置 | 主要基于经验 | 主要基于统计指标 |
| 实施成本 | 较低 | 较高 |
| 实际使用 | 通常与量化规则结合 | 通常与经验规则结合 |

### 3.3 变量开发要点

变量开发是规则制定的基础，应分阶段持续建设：

| 阶段 | 内容 | 示例 |
|---|---|---|
| 第一阶段 | 建设核心变量 | 征信衍生变量 |
| 第二阶段 | 扩展补充维度 | 设备、消费、行为变量 |
| 第三阶段 | 新数据源迭代接入 | 新三方变量、产品行为变量 |

变量开发之前，必须同步明确：

- 分析样本方案
- OOT 样本方案
- 变量回溯口径
- 标签定义

## 四、单变量规则开发方法

### 4.1 开发三步流程

1. 变量初筛
2. 分箱与指标计算
3. 阈值制定与效果评估

展开后可理解为：

```text
Step 1 变量初筛
  -> 描述性统计
  -> 缺失率分析
  -> 众数占比分析
  -> 剔除无效变量

Step 2 分箱与指标计算
  -> 连续变量离散化
  -> 离散变量合并归类
  -> 计算分箱统计量
  -> 计算 WOE / IV

Step 3 阈值制定
  -> 基于分箱效果选阈值
  -> 基于极端值测试阈值
  -> 输出规则评估指标
```

### 4.2 变量初筛淘汰标准

| 淘汰原因 | 判断标准 | 案例 |
|---|---|---|
| 缺失率过高 | 显著影响稳定性 | 缺失率 60% 以上 |
| 众数占比过高 | 几乎无区分能力 | 90% 以上取值相同 |
| 无法分箱 | 缺乏排序性或信息量极低 | 数值虽存在但无有效差异 |

### 4.3 分箱（Binning）核心知识

分箱是将连续变量离散化，或对离散变量合并归类，以便统计分析和规则制定。

分箱示例：

| 原始值 | 分箱结果 |
|---|---|
| 成绩 < 60 | 不及格 |
| 60 <= 成绩 < 80 | 及格 |
| 成绩 >= 80 | 优秀 |

分箱原则：

| 原则 | 要求 |
|---|---|
| 全覆盖 | 覆盖变量全部取值 |
| 数量适中 | 一般控制在 5~8 箱 |
| 每箱有量 | 每箱样本占比最好不低于 5% |
| 缺失独立 | 缺失值建议单独成箱 |

常用分箱算法：

| 变量类型 | 常用算法 |
|---|---|
| 连续型变量 | 卡方分箱、最优分箱、决策树分箱、KS 分箱、等频、等距 |
| 离散型变量 | 类别合并归类 |

### 4.4 分箱核心统计指标

以“近3个月新型非银机构查询次数”为例，分箱后常看以下指标：

| 指标 | 定义 | 计算方向 | 用途 |
|---|---|---|---|
| 数量统计 | 好客户数、坏客户数、总客户数 | 基础统计 | 基础数据 |
| 边际好客户占比 | 箱内好客户数 / 全部好客户数 | 纵向 | 衡量误拒 |
| 边际坏客户占比 | 箱内坏客户数 / 全部坏客户数 | 纵向 | 衡量拦截能力 |
| 区间占比 | 箱内客户数 / 总客户数 | 横向 | 近似规则命中率 |
| 区间坏账率 | 箱内坏客户数 / 箱内总客户数 | 横向 | 近似规则精准率 |

### 4.5 WOE 与 IV

#### 4.5.1 WOE 的定义

WOE（Weight of Evidence，证据权重）是变量的一种有监督编码方式，用于衡量每个分箱中坏客户分布相对好客户分布的差异。

计算前提：

1. 样本有明确标签 Y
2. 变量已完成分箱

WOE 公式：

$$
WOE_i=\ln\left(\frac{Bad_i/Bad_T}{Good_i/Good_T}\right)
=\ln\left(\frac{Bad_i}{Good_i}\right)-\ln\left(\frac{Bad_T}{Good_T}\right)
$$

其中：

- `Bad_i`：第 i 箱坏客户数
- `Bad_T`：总体坏客户数
- `Good_i`：第 i 箱好客户数
- `Good_T`：总体好客户数

#### 4.5.2 WOE 的含义

- WOE 越大，通常说明该区间坏账率越高
- WOE 为正，偏向坏客户方向
- WOE 为负，偏向好客户方向
- 经验上 WOE 常落在 `(-3, 3)` 范围内

WOE 可以从两个角度理解：

1. Odds 视角：第 i 箱坏好比相对总体坏好比的对数差
2. 贝叶斯视角：后验认知相对先验认知的修正增量

贝叶斯形式可写为：

$$
\ln\frac{P(Y=Bad\mid X)}{P(Y=Good\mid X)}
=\ln\frac{P(X\mid Y=Bad)}{P(X\mid Y=Good)}
+\ln\frac{P(Y=Bad)}{P(Y=Good)}
$$

#### 4.5.3 为什么要做 WOE 编码

- 增强泛化能力：将连续变量转换为有限分箱值，降低噪声
- 提高可解释性：WOE 的符号和大小可解释风险方向和程度
- 提升变量稳定性：分箱可平滑异常值与缺失值
- 便于评分卡建模：统一量纲，有利于逻辑回归拟合
- 便于推导 IV：为变量筛选提供基础

#### 4.5.4 IV 的定义

IV（Information Value，信息价值）用于衡量变量对目标变量的预测能力。

$$
IV_i=\left(\frac{Bad_i}{Bad_T}-\frac{Good_i}{Good_T}\right)\times WOE_i
$$

$$
IV=\sum_{i=1}^{n}IV_i
$$

#### 4.5.5 IV 与 WOE 的关系

WOE 反映的是区间差异方向和强弱，但不考虑样本权重；IV 则在 WOE 基础上加入样本占比权重，因此更适合衡量变量整体预测能力。

重要结论：

- 某分箱 WOE 很高，不代表变量整体贡献一定高
- 如果该分箱样本占比很低，IV 可能仍然较低

#### 4.5.6 IV 的应用与评估标准

| IV区间 | 解释 | 业务建议 |
|---|---|---|
| <= 0.02 | 很弱 | 通常剔除 |
| (0.02, 0.1] | 偏弱 | 谨慎使用 |
| (0.1, 0.3] | 中等 | 可用 |
| (0.3, 0.5] | 较强 | 优先使用 |
| > 0.5 | 很强 | 需排查数据穿越 |

补充说明：

- 贷前、贷中、贷后不同场景的 IV 水平不可直接横向比较
- 某些子模型环境下，全部变量 IV 都较低，此时更应关注相对值

#### 4.5.7 WOE / IV 使用注意事项

- 每箱样本量不能过少，通常要求占比至少约 5%
- 若某箱全为好或全为坏，需要做平滑处理，避免分母为 0
- 缺失值建议单独成箱
- 分箱数量不宜过多，一般不超过 8 箱
- 相邻箱 WOE 相同或接近时可考虑合并
- 分箱越多，IV 往往越大，不可为了提高 IV 盲目细分
- 贷前变量 IV 异常高时，需重点排查数据穿越

## 五、规则阈值制定与效果评估

### 5.1 规则效果的两大目标

| 目标 | 含义 | 业务原因 |
|---|---|---|
| 命中率不宜过高 | 单条规则拒绝比例一般不宜超过 5% | 避免明显伤害通过率 |
| 精准率尽可能高 | 命中客户中坏客户浓度越高越好 | 抓坏客户、少误杀好客户 |

### 5.2 五大评估指标

| 指标 | 定义 | 计算方式 | 说明 |
|---|---|---|---|
| 命中率 Hit Rate | 规则命中客户占总客户比例 | 命中客户数 / 总客户数 | 反映拒绝比例 |
| 精准率 Precision | 命中客户中坏客户占比 | 命中坏客户数 / 命中客户数 | 反映坏客户浓度 |
| 召回率 Recall | 命中的坏客户占全部坏客户比例 | 命中坏客户数 / 总坏客户数 | 反映拦截覆盖能力 |
| 排序性 | 分箱坏账率是否单调 | 无固定公式 | 反映规则可解释性 |
| 可解释性 | 是否符合业务认知 | 无固定公式 | 反映落地可接受程度 |

精准率与召回率通常相互制衡：

```text
精准率提高，召回率可能下降
召回率提高，精准率可能下降
```

因此不能只追求某一项指标。

### 5.3 方法一：基于分箱的 IV 分析法

步骤：

1. 对变量进行分箱
2. 计算各箱坏账率、客户占比、WOE、IV 等
3. 选择坏账率高且命中率可接受的区间作为阈值
4. 输出命中率、精准率、召回率、Lift 等指标

案例：

| 评估项 | 数值 | 解读 |
|---|---:|---|
| 规则定义 | 查询次数 > 4 | 触发即拒绝 |
| 命中率 | 5.01% | 拒绝比例可接受 |
| 精准率 | 18.87% | 命中客群坏账浓度较高 |
| 整体坏账率 | 6.43% | 基线 |
| Lift | 2.93 | 区分能力为基线 2.93 倍 |
| 召回率 | 14.71% | 抓到 14.71% 的坏客户 |
| 好客户误拒率 | 4.34% | 可控 |

### 5.4 方法二：极端值检测法

核心思想：高风险客群常分布在变量的极端区间。

步骤：

1. 选取极端分位点作为候选阈值
2. 分别生成规则
3. 计算各规则 Hit Rate、Precision、Recall、Lift
4. 综合比较确定最优阈值

常见候选分位点：

- `0.5%`
- `1%`
- `2%`
- `5%`
- `95%`
- `98%`
- `99%`
- `99.5%`

适用类型：

| 变量逻辑类型 | 含义 | 示例 |
|---|---|---|
| 极小值风险高 | 数值越小，风险越高 | 公积金缴存基数 |
| 极大值风险高 | 数值越大，风险越高 | 征信查询次数 |

### 5.5 Lift 指标

#### 5.5.1 Lift 的定义

Lift（提升度）衡量规则或模型相对随机筛选的提升倍数。

在风控场景中，本质是衡量规则对坏客户的识别能力相对于总体基线坏账率的增益。

最常用定义：

$$
Lift=\frac{规则精准率}{整体坏账率}
$$

示例：

- 整体坏账率 = 6%
- 规则精准率 = 18%
- Lift = 3

即规则识别能力约为随机基线的 3 倍。

#### 5.5.2 Lift 的两种常见计算逻辑

1. 区间 Lift：`区间坏账率 / 总体坏账率`
2. 累计 Lift：`累计坏样本占比 / 累计总样本占比`

区间 Lift 用于看某个分层或某条规则的局部识别能力；累计 Lift 常用于分数卡或模型排序可视化。

#### 5.5.3 Lift 的评估标准

| Lift 与 1 的关系 | 含义 |
|---|---|
| Lift > 1 | 优于随机筛选 |
| Lift = 1 | 与随机筛选相同 |
| Lift < 1 | 不如随机筛选 |

经验上，在信贷场景中：

- `Lift > 1` 说明有效
- `Lift > 3` 通常说明效果较好

但最终阈值仍需结合业务成本、通过率和召回率综合判断。

#### 5.5.4 Lift-chart 解读

Lift 曲线通常要求：

- 越平滑越好
- 越陡峭越好

越陡峭意味着头部样本集中更多坏客户，排序能力更强。

## 六、交叉表规则开发方法

### 6.1 交叉表定位

交叉表规则处于单变量规则与模型之间，是一种兼顾可解释性和多维识别能力的中间形态。

```text
单变量规则 -> 交叉表规则 -> 模型
简单直接      复杂度适中     复杂但更强
```

### 6.2 交叉表核心特点

| 特点 | 说明 |
|---|---|
| 多维评估 | 同时考虑两个及以上变量 |
| 信息更丰富 | 不同变量组合下坏账率差异更清晰 |
| 复杂度适中 | 比单变量复杂，但比模型更易解释 |

### 6.3 生成交叉表的前置条件

| 条件 | 要求 | 说明 |
|---|---|---|
| 变量筛选 | 变量本身区分能力较好 | 一般基于 IV 等指标筛选 |
| 变量组合 | 变量最好来自不同维度、相关性低 | 避免信息重复 |
| 样本量充足 | 交叉后每个格子仍有统计意义 | 防止过细分导致不稳定 |

### 6.4 交叉表规则生成三步法

1. 制作透视表
2. 计算每个格子的坏账率和客户占比
3. 选择高坏账率且命中率可接受的格子制定规则

透视表通常至少包含：

- 每格总客户数
- 每格坏客户数
- 每格坏账率
- 每格客户占比

### 6.5 应用案例

业务背景：市场环境恶化，希望在不显著降低通过率的前提下提高风险拦截能力。

方案对比：

| 方案 | 规则定义 | 命中率 | 区间坏账率 | Lift |
|---|---|---:|---:|---:|
| 交叉表规则 | 最近6个月新开信贷账户数 >= 3 且 公积金状态为特定值 | 1.68% | 51.52% | 约 7x |
| 单变量规则 | 最近6个月新开信贷账户数 >= 3 | 8.19% | 25.47% | 约 4x |

结论：交叉表规则在更低命中率下获得更高坏账率，适合精细化调优。

## 七、决策树规则开发方法

### 7.1 决策树核心概念

决策树是一组规则的集合，通过不断选择变量及阈值对样本进行分裂，最终在叶子节点输出风险结论。

```text
根节点
 -> 内部节点（继续分裂）
 -> 叶子节点（输出结果）
```

### 7.2 常见决策树算法

| 算法 | 适用场景 | 特点 |
|---|---|---|
| ID3 | 分类 | 早期算法，不擅长连续变量 |
| C4.5 | 分类 | 可处理连续变量 |
| CART | 分类/回归 | 二叉树结构，工程最常用 |

风控规则开发中，重点使用 CART。

### 7.3 CART 分类树：基尼指数

在二分类场景中，基尼指数常写为：

$$
Gini = 2p(1-p)
$$

其中 `p` 为某一类别的占比。

解释：

- 当好坏客户各 50% 时，Gini 最大，纯度最差
- 当全为好或全为坏时，Gini = 0，纯度最高

变量选择过程：

1. 遍历候选变量
2. 对连续变量找切分点，对离散变量做二分归组
3. 计算每种切分方式的 Gini
4. 选择 Gini 最小的切分方式

### 7.4 CART 回归树

| 维度 | 分类树 | 回归树 |
|---|---|---|
| 预测目标 | 类别 | 连续数值 |
| 度量标准 | 基尼指数 | 残差平方和 |
| 输出结果 | 类别或概率 | 数值均值 |

### 7.5 决策树规则生成示例

示例规则：

`过去3个月查询机构数 > 6` 且 `无公积金` -> 拒绝

示例分组：

| 客群 | 坏账率 | 特征描述 |
|---|---:|---|
| 优质客群 | 3% | 查询机构数低且有稳定资产 |
| 中等客群 | 5% | 查询机构数高但有房产 |
| 中高风险客群 | 8% | 查询不高但无公积金 |
| 高风险客群 | 12% | 查询高且无公积金 |

### 7.6 决策树规则使用注意事项

- 单条树规则包含的变量数量通常不宜超过 3 个
- 树深度不能过深，避免过拟合
- 离线效果好不代表 OOT 效果好
- 规则必须具备业务可解释性
- 规则过于复杂会增加维护与异常排查难度

## 九、规则集认识与结构

### 9.1 什么是规则集

规则集是一系列规则的集合，在策略中通常对应一个决策节点。

示例：

```mermaid
flowchart LR
    A[准入规则集] --> B[黑名单规则集] --> C[反欺诈规则集] --> D[征信规则集] --> E[多头规则集]
```

例如：

- 多条征信规则组合成“征信规则集”
- 多条多头规则组合成“多头规则集”

### 9.2 规则集的三种结构

1. 串行规则集
2. 并行规则集
3. 串行并行组合规则集

### 9.3 串行结构

串行结构表示规则按顺序依次执行：

```text
规则1 -> 规则2 -> 规则3 -> ... -> 规则N
```

特点：

- 某条规则命中后，后续规则不再执行
- 每条规则都会形成一定拒量
- 整体呈现漏斗结构
- 适用于有优先级、需节约调用成本的场景

示例：内部黑名单优先于外部付费黑名单，以降低调用成本。

### 9.4 并行结构

并行结构表示所有规则同时执行。

特点：

- 各规则互相独立
- 客户可同时命中多条规则
- 命中任意一条即可拒绝
- 适合用于规则监控、组合分析和调优

### 9.5 串行与并行对比

| 维度 | 串行规则集 | 并行规则集 |
|---|---|---|
| 执行效率 | 通常更高 | 通常更低 |
| 数据获取 | 后续未执行规则无表现数据 | 所有规则都有表现数据 |
| 监控分析 | 相对困难 | 更方便 |
| 使用场景 | 有优先级排序 | 无优先级，强调后续分析 |

## 十、规则集线下性能测试

### 10.1 分析流程

```mermaid
flowchart LR
    A[01 规则挖掘：单变量、交叉表、决策树规则]
    B[02 规则评估：命中率、精准率、召回率]
    C[03 规则集线下性能测试]
    D[04 规则集线上效果监控]
    E[05 规则调优]
    A --> B --> C --> D --> E
```

### 10.2 三类核心指标

规则集线下性能测试通常包含三类指标：

1. 综合命中率
2. 整体坏账率
3. 相互覆盖率与单一命中率

### 10.3 综合命中率

综合命中率指规则集作为整体的最终命中率。

关键点：

- 不等于内部单条规则命中率简单求和
- 因为规则之间往往存在交叉命中
- 规则集拒绝条件不同，整体命中率也会不同

示例：

- 命中至少 1 条即拒绝：整体命中率较高
- 命中至少 2 条即拒绝：整体命中率较低，但通常更保守

公式：

$$
综合命中率=\frac{规则集命中样本数}{样本总数}
$$

### 10.4 整体坏账率

整体坏账率用于衡量规则集命中客群的风险浓度。

计算逻辑：

1. 先根据规则集逻辑确定哪些客户命中
2. 再统计命中客户中的坏客户占比

公式：

$$
整体坏账率=\frac{规则集命中客户中的坏客户数}{规则集命中客户数}
$$

它反映的是规则集作为整体决策单元的识别能力。

### 10.5 相互覆盖率与单一命中率

相互覆盖率用于分析规则之间的重叠程度；单一命中率用于分析规则是否有独立贡献。

重要原则：

- 如果一条规则完全被其他规则覆盖，则独立价值较低
- 完全被覆盖通常等价于单一命中率为 0
- 应先剔除无效规则，再重新计算单一命中率

应用价值：

- 降低重复规则数量
- 提高规则集可维护性
- 保留真正有独立贡献的规则

### 10.6 规则集案例分析要点

对于候选规则集，建议输出如下表头进行横向比较：

| 字段 | 含义 |
|---|---|
| `rule_id` | 规则编号 |
| `rule_name` | 规则表达式 |
| `bad_rate` | 规则命中客群坏账率 |
| `hit_rate` | 规则命中率 |
| `recall_rate` | 召回率 |
| `lift` | 提升度 |

这类结果表适用于：

- 候选规则排序
- 去重筛选
- 组合成规则集前的优先级评估

## 十一、规则泛化效果评估

### 11.1 为什么要做泛化评估

规则在分析样本上效果好，不代表上线后依然有效。上线前必须验证规则在时间外样本（OOT）上的稳定性和泛化能力。

### 11.2 泛化评估与规则筛选评估的区别

规则开发中存在两类评估：

1. 规则筛选评估：用于从候选规则中筛出好规则，关注命中率、精准率、召回率等
2. 泛化效果评估：用于评估规则对业务影响，关注逾期率、通过率等

两者使用的部分指标相同，但问题不同、目标不同。

### 11.3 泛化评估通用流程

```mermaid
flowchart LR
    A1[人工制定规则：风险识别] --> A2[人工规则] --> A3[变量开发] --> A4[样本选取]
    B1[量化制定规则：变量开发] --> B2[样本选取] --> B3[量化规则]
    A4 --> C[效果评估]
    B3 --> C
    B3 --> D[规则筛选指标：命中率、精准率、召回率]
    C --> E[业务影响评估：逾期率、通过率]
```

具体流程：

1. 选择合适的泛化样本
2. 回溯并加工规则涉及的底层变量
3. 在泛化样本上复现规则或规则集
4. 计算评估指标并与分析样本对比

注意：虽然泛化评估位于离线开发后段，但泛化样本设计和变量回溯方案必须在前期就确定。

### 11.4 逾期率效果评估

#### 11.4.1 OOT 样本要求

时间外样本通常需要满足以下条件：

1. 时间窗口在分析样本之后
2. 样本量满足统计意义，一般建议 3 个月以上并按月评估
3. 有足够贷后表现期
4. 客群与风险水平与分析样本尽量同质

示意：

- 分析样本：过去一段完整历史窗口
- OOT 样本：分析样本之后的未来窗口
- 观察截止：确保 OOT 样本已具备充分贷后表现

#### 11.4.2 评估指标

逾期率效果评估常用指标包括：

- 命中率
- 精准率
- 召回率
- Lift
- 逾期率下降幅度

公式：

$$
命中率=\frac{规则命中样本数}{样本总数}
$$

$$
精准率=\frac{规则命中样本中的坏客户数}{规则命中样本数}
$$

$$
召回率=\frac{规则命中样本中的坏客户数}{样本总坏客户数}
$$

$$
Lift=\frac{精准率}{样本总坏账率}
$$

$$
逾期率下降幅度=\frac{样本总坏账率-规则通过样本坏账率}{样本总坏账率}
$$

#### 11.4.3 泛化判断原则

- 若 OOT 样本指标在分析样本附近小幅波动，说明泛化较好
- 若关键指标明显衰减，则可能存在过拟合

经验上常参考：

- 一般浮动不超过约 10%
- 严格场景可控制在 5% 以内

例如：

- 分析样本 Lift = 3
- OOT 样本 Lift = 1

则说明规则衰减严重，需重新调整。

### 11.5 通过率效果评估

评估通过率不需要完整贷后表现，因此可以使用更接近当前的新鲜样本。

关键点：

- 逾期率评估样本与通过率评估样本可以不同
- 新鲜样本同样需要变量回溯
- 核心关注规则应用前后的命中率和通过率变化

### 11.6 泛化评估常见误区

- 只看分析样本，不看 OOT 样本
- 只看精准率，不看通过率影响
- 没有提前做变量回溯规划
- 只评估单条规则，不评估规则集整体效果

## 十三、关键经验总结与常见误区

### 13.1 核心原则速查

1. 规则开发前，必须先完成样本设计与变量准备。
2. 单条规则命中率一般不宜过高，否则会明显伤害通过率。
3. 变量筛选遵循“好而不同”：IV 高且相关性低。
4. 连续型变量分箱后必须检查排序性与稳定性。
5. IV 异常高时优先排查数据穿越。
6. 决策树规则不能只看离线效果，还要控制复杂度。
7. 规则集要重视覆盖关系与独立贡献，不要机械堆规则。
8. 所有规则都必须具备业务可解释性。
9. 泛化评估方案和变量回溯方案必须提前准备。

### 13.2 经验观点与数据验证

| 经验型观点 | 数据验证方式 |
|---|---|
| 查询次数越多，多头风险越高 | 看高查询区间坏账率、Lift、召回率 |
| 设备长期不活跃可能非真人使用 | 看沉默设备人群的坏账浓度与命中率 |
| 公积金弱、资产弱人群风险高 | 看交叉表规则下坏账率是否显著上升 |

### 13.3 常见误区

| 误区 | 正确做法 |
|---|---|
| 规则越多越好 | 关注独立贡献和重复覆盖 |
| IV 高的变量全部保留 | 同时看相关性、稳定性、业务含义 |
| 精准率越高越好 | 必须结合命中率和召回率一起看 |
| 一条规则解决所有问题 | 风控是分层漏斗式协同 |
| 决策树越深越好 | 深度过大更容易过拟合 |
| 只看离线效果 | 必须做 OOT 泛化评估和上线监控 |

- case2 第 8 箱 WOE 高于 case1

### A.3 Python 手动实现 WOE / IV

```python
def feature_woe_iv(x, y, boundary=None, nan=-1):
    x = x.fillna(nan)
    split = boundary if boundary else optimal_binning_boundary(x, y, nan)
    df = pd.concat([x, y], axis=1)
    df.columns = ["x", "y"]
    df["bins"] = pd.cut(x=df["x"], bins=split, right=False)
    grouped = df.groupby("bins")["y"]
    result_df = grouped.agg([
        ("good", lambda s: (s == 0).sum()),
        ("bad",  lambda s: (s == 1).sum()),
        ("total", "count")
    ])
    result_df["good_pct"] = result_df["good"] / result_df["good"].sum()
    result_df["bad_pct"] = result_df["bad"] / result_df["bad"].sum()
    result_df["total_pct"] = result_df["total"] / result_df["total"].sum()
    result_df["bad_rate"] = result_df["bad"] / result_df["total"]
    result_df["woe"] = np.log(result_df["bad_pct"] / result_df["good_pct"])
    result_df["iv"] = (result_df["bad_pct"] - result_df["good_pct"]) * result_df["woe"]
    result_df["feature"] = x.name
    iv_value = result_df["iv"].sum()
    return result_df, iv_value
```
